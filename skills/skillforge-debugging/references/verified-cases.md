# 案例与证据

## DBG-K01：把旧经验当作输入规则

| 字段 | 内容 |
|---|---|
| 状态 | 本机源码已核验，并与当前官方 API 页对照；未执行真实界面的输入回归 |
| 症状与条件 | 子按钮可见却不可点击，祖先可能使用 `HitTestInvisible` |
| 版本 | 核验 UE 5.7.4；其他版本调用时复核 |
| 证据 | 引擎相对路径 `Engine/Source/Runtime/UMG/Public/Components/SlateWrapperTypes.h` 的 `ESlateVisibility`；[Epic API 当前页](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/UMG/ESlateVisibility)（本次读取显示 5.8，5.7 结论依据本机源码） |
| 原因 | `Hidden` 占位但不可命中；`HitTestInvisible` 同时禁止自身及子控件命中；`SelfHitTestInvisible` 只排除自身。历史 LGF 笔记中的“Hidden 仍可点击”不成立 |
| 修复方向 | 对只绘制、自身无需输入且包含交互子控件的容器，核对是否应使用 `SelfHitTestInvisible`；父级也需输入时另查需求 |
| 验证结果 | 枚举语义已确认，特定故障根因未确认；应检查运行实例、命中路径和一次点击对应的业务动作，并回归动态隐藏与重复打开 |

这里收录的是机制与诊断方法，不是“所有点不到的按钮都改这一属性”。遮挡、启用状态、焦点、捕获与绑定仍可能造成相同症状。

## DBG-K02：面板不更新时直接加延迟

| 字段 | 内容 |
|---|---|
| 状态 | 方法候选；来自项目维护资料，当前插件未运行验证 |
| 症状与条件 | 订阅或加载入口发生变化后，界面偶发不刷新 |
| 版本 | 客户端与框架版本须在任务现场识别 |
| 证据 | Replicated Suite 维护资料中的加载入口、能力状态与刷新链约束；具体案例必须再补当前入口、日志或复现 |
| 原因 | 尚未确认；可能是注册、实例过期、状态未提交或刷新请求未消费 |
| 修复方向 | 沿入口至展示找首个断点；若证实数据未就绪，等待明确就绪条件，而不是凭旧笔记追加秒数 |
| 验证结果 | 没有游戏运行数据；准备实例/请求/状态关联记录后重跑原路径，不能宣称延迟修复有效 |

方法参考：[Superpowers 排障流程](https://github.com/obra/superpowers/blob/b36e0829c6d0140e93cfef2ca599b1b07d4a7797/skills/systematic-debugging/SKILL.md)。本技能按任务调整调查深度，并保留未确认状态。

## DBG-K03：把工具的沉默当作事实，并据此写资产

| 字段 | 内容 |
|---|---|
| 状态 | 已复现，并造成真实返工（改动二进制资产后靠备份+哈希还原） |
| 症状与触发条件 | 用离线解析器 dump 资产属性，目标属性没出现在输出里，据此判定“该属性未设置 ⇒ 使用 C++ 默认值”，并据此批量写资产 |
| 版本 | UE 5.7；UAssetAPI 系离线解析器 |
| 证据 | 同一属性在解析器输出中不存在，但运行时反射读到的是**已设置的非默认值**；解析器只遍历它实现的导出属性子集 |
| 原因 | 把“我没读到”当成“它不存在”。工具的覆盖范围不等于事实的覆盖范围；未序列化不等于未设置，也可能只是解析器没 dump |
| 修复 | 写二进制资产前必须用权威通道读回（运行时反射、编辑器内查看），不能靠“缺失即默认”的推断；解析器输出只用于定位，不用于断言缺失 |
| 验证结果 | 本次以 `sha256` 备份还原并核对与版本库一致。教训是顺序性的：先证实，再写；写之前先假定自己的读法是残缺的 |

## DBG-K04：探针在故障态不会触发

| 字段 | 内容 |
|---|---|
| 状态 | 已复现，浪费一整轮运行验证 |
| 症状与触发条件 | 加了诊断日志后跑一次，日志为空，于是判定“该链路正常” |
| 版本 | 与版本无关，属方法缺陷 |
| 证据 | 条件被写成 `if (Target != Displayed) log`；而真实故障恰是 `Target` 恒为 0、`Displayed` 也为 0，两者相等 ⇒ 永不打印。另一例：探针检查组件的可见性标志，而症状是屏幕空间控件仍留在视口图层里 |
| 原因 | 探针条件从“我预期的失败形状”推出，而不是从“故障态必然可观测”推出 |
| 修复 | 加探针前先回答“最坏情况下它会打印吗”。优先无条件输出 + 状态签名去重（把关键字段 `Printf` 成签名串，与上一次比较），不要用阈值不等式当触发条件；并且不要依赖需要每局重设的调试开关 |
| 验证结果 | 改为状态签名后，一次运行即给出“阶段未翻转而队列已在进行中”的决定性对照。未覆盖：探针仍可能因日志类别被过滤而看不到，需确认输出落在哪个类别 |

## DBG-K05：同类缺陷逐个修，不扫同型

| 字段 | 内容 |
|---|---|
| 状态 | 已复现（同一会话内同一模式出现 4 次，每次都是新症状才修一处） |
| 症状与触发条件 | “销毁时解绑、重绑只发生在一次性初始化路径”这一模式，分别造成按钮失效、结果收不到、队列刷新丢失、面板不重建 |
| 版本 | UE 5.7 UMG/C++ |
| 证据 | 四处代码同构：绑定在 `NativeOnInitialized`/`BeginPlay`/受“指针是否变化”门控的解析函数，解绑在 `NativeDestruct`/`EndPlay` |
| 原因 | 流程问题而非认知问题：确认机制后没有立刻做全库同型检索，等到下一个症状出现才回头 |
| 修复 | 一旦确认某类机制缺陷，马上按**机制**检索（例如比较每个控件类里 Bind 与 Unbind 所在函数是否同层），一次列出全部命中再决定范围；顺带确认哪些同型位置实际不受影响，避免把猜测写成缺陷 |
| 验证结果 | 第 4 处正是靠同型检索找到的；同仓库另一处同类控件经检索确认不受影响，未改。未覆盖：未跨模块统计，只覆盖当次工程 |
