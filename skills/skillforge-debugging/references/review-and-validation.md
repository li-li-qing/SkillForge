# 多轮审查与长任务的证据管理

用于前序 AI 结论冲突、跨版本测试、无 Git 工程或多人轮流写同一工程。普通小问题不强制完整审计仪式。

## 从承重结论回到证据

先列用户目标、全部被审交付及未完成项，再把影响后续决策的主张逐项映射到源码/资产/运行证据。不要只审提示词突出列举的几个故障，遗漏清单其他任务。历史记录、当前代码、获准设计和本轮执行分别标注。

逐环核对调用栈和时序，而非只看函数存在。输出“确认/部分确认/推翻/无法判定”，给出观察、竞争解释、能够区分解释的最小实验。没有留存日志不证明其他运行通道从未发生；mtime 不证明作者，快照哈希只证明内容。

## 长任务与共享现场

- 建立一份任务台账：范围、依赖、owner、证据、状态、剩余验证。快照只供历史追溯，不另建冲突的现行状态真值。
- 每轮恢复先读检查点并刷新现场：时间、运行进程、锁、变更文件。锁属于别人时不抢占或删除，做不冲突的只读工作。不存在锁也不代表没有编辑器/构建在运行。
- 无 Git 时对本轮目标及必要依赖做相对路径备份和内容校验，覆盖会写的配置、资产和源码；P4/现有版本控制能提供的归属与差异直接复用。记录新增/删除/无法读取项。只有承诺证明全工程未变时才做完整集合核验，不能把一次局部检查扩大表述成全工程未变，也不每个小改重复全盘freeze。
- 按项目约定领取排他锁，只有持有者释放；共享文档若要求纯追加，验证原文前缀不变和删除行数为零，不用整篇重写覆盖别人的记录。
- 检查点写完成内容、进行中的进程/日志、阻塞证据及下一条实际动作。中断恢复不反复从头读完整历史，也不反复发送同样的“继续等待”。
- 多 Agent 仅在获准时启用。记录实际审阅者与输入版本；同一作者自查不是独立复核，未运行的互审不写成全员通过。

## 防止假绿

| 观察 | 不能推出 | 需要补充 |
|---|---|---|
| 退出码 0 | 测试通过 | 报告正文断言、失败/跳过数量、Error/ensure 与 Result |
| 旧版本回归全绿 | 当前改动通过 | 相关源码、资产与实际二进制版本关联；变化后重跑受影响验证 |
| 生成器输出与生成器算法相同 | 输入语义正确 | 独立来源、周期/单位/身份/几何等行为不变量 |
| 设置值改变 | 用户效果生效 | 最终消费者和实际输出，例如绝对控件大小、真实连接状态 |
| 所有阶段标记完成 | 套件成功 | 保留阶段内失败断言；不能以末尾完成标记覆盖 Fail |
| 局部复制断言通过 | 战斗/网络全链通过 | 明确用例整体及各子断言，命中/伤害/视觉分别验收 |
| 构建返回“up to date / 全部最新” | 本轮发生了重新编译，或当前运行进程已加载新逻辑 | 核对目标、输入版本与产物/已加载版本的关联；刚改过输入却仍显示最新时查缓存和目标选择。输入与产物一致时可复用增量结果，不为出现 Compile 行而强制重编 |
| 跨文件冲突修复后构建通过 | 冲突场景被重新编译过 | 确认被修改文件仍与冲突方处于同一编译单元；增量/自适应机制可能恰好把它移出该单元，使故障场景在本次构建中不存在 |

先固定预期用例的完整身份集合，再与实际报告逐项比对：缺失、未注册、被过滤、跳过、失败分别记录。四个Success不能替代预期五个；多次报告按用例身份及输入版本取并集，不累计重复项。旧Host通过不自动补齐当前主工程，反过来也一样。只补缺失项和输入变化影响的相关用例，不为合成一次命令而重跑已足够的证据。

故障先定位到准备/调用/产品/清理阶段。查错组件owner、能力未授予、脚本绑定/参数错误或未进入目标分支时，不记为该产品缺陷的RED；保留原始失败并修复夹具。先读构造器/已有有效夹具确定归属；必需组件不存在时具名早失败，真实异步未就绪才有界等待。“Complete”可能包含Failed，另查成功状态；请求已受理也要关联最终结果。契约已明确改变时可以等价更新旧测试前提，保留原业务场景和断言，不能删失败断言、放宽权限或用完成标记抹掉失败。

验证结果用独立列而非一个含混等级：源码静态、构建、资产加载/索引、无头运行逻辑、实际网络拓扑、渲染视觉、人工验收、发行包。NullRHI 可以运行某些真实网络逻辑，但不能证明画面质量；宿主拥有 Authority 不等于 Remote RPC 已覆盖。

负测必须真能暴露断点。资产持久化门禁采用隔离副本 → 制造受控坏值 → 官方保存 → 新进程运行门禁失败 → 恢复 → 新进程通过 → 官方删除并查残留。只改内存后在同进程调用另一个函数不能证明独立命令会拒绝磁盘坏资产。

最终报告保留失败与警告原文，区分原始日志行数和去重问题数。证据采集在运行中开始就如实写运行中，不能事后称为运行前基线。没测写未执行，不把“基本正常”当状态。
