# LGF 消费工程跨版本升级检查点

用于同时涉及引擎、LGF、GASP 示例、工程命名和玩家外观的迁移。把这些变化分开落地，才能知道新故障最早出现在哪层。此处是迁移方法；具体 UE 版本、插件 API、资产名和数值始终以目标工程为准。长任务状态记录在消费工程的一份阶段清单中，延续原编号与证据。

| 检查点 | 操作与可观察完成条件 |
|---|---|
| 输入冻结 | 记录源工程/P4 或 Git 版本、未提交与被忽略的必需文件、引擎 Build.version、`.uproject`、LGF `.uplugin` 与 `Build.cs`、GASP/第三方交付版本、资产清单及关键哈希；保留原工程和交付原件。新目录复制后核对清单/哈希，排除可重建缓存与旧工作区写入配置。 |
| 原版基线 | 在旧引擎构建/加载旧工程，跑与玩家、动画和关键玩法有关的检查，记录原有失败。没有可运行基线时说明证据缺口，不能把升级后所有错误都归因于新版本。 |
| 只升级引擎 | 在隔离工程保持旧命名、旧角色和旧 GASP 链，按实际错误适配 Target、模块、LGF 与版本变化；Editor/Game 构建后再验证蓝图、地图和旧玩家运行。LGF 的 Authority/Request 与 Mover 的模拟责任不得被新示例 Pawn 悄悄替换。 |
| 命名迁移 | 为项目自有模块、Targets、反射类型、资产和软路径制作旧→新映射并查重名；第三方与 LGF 身份保持原样。反射类型用精确 Core Redirects，资产用编辑器移动/重命名并修 Redirector、配置、Cook 路径；不全局替换项目短名，不文本改写 `.uasset`。再次构建和加载旧角色。 |
| 新版 GASP 对照 | 把新版示例当 donor：审计 Pawn/AnimBP/Chooser/PoseSearch/Mover/PhysicsControl 等真实差异，逐项判断是否与现有玩家合同兼容。新示例好玩或节点更多，不等于可以整目录覆盖；只迁有明确收益和验证路径的部分，保留可回滚映射。 |
| 第三方角色与动作 | 用真实 Asset Registry/对象依赖建立交付闭包，核对 Skeleton、SkeletalMesh、材质、PhysicsAsset、Retargeter、动画与插件依赖；同路径冲突逐项比较，不盲目覆盖。先让旧玩家在新引擎继续工作，再接可见 Mesh、面颈、装备与预览样本；完整动作库迁入不等于正式技能动作已切换。运行时重定向的面颈/脚底诊断由 UE 蓝图技能处理。 |
| 分层交付 | 分别报告 UBT/UHT、蓝图/资产加载、自动化匹配数与结果正文、Error/Ensure、PIE 渲染、多网络角色、Cook/成品启动和人工视觉手感。NullRHI 或命令行加载不能代替视觉；安装版引擎未提供的独立 Server 构建不能写成通过。每阶段只修该阶段新引入问题，回滚新工程快照，不回写源工程。 |

引擎版本变更后，先检查目标版本官方源码/文档与实际插件声明；历史迁移报告和示例 README 只用于提出待验证差异。若连接编辑器的 MCP/Python 工具可用，先确认当前进程、项目、工具范围和读写能力，再用小范围只读探针；编辑器会话成功不等于命令行或打包环境可用。临时远程端点和调试设置用完恢复。
