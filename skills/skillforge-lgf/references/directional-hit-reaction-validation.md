# 方向受击、锁敌与摄像机：诊断和验证

用于 LGF + GASP/Mover 中受击方向固定、锁敌受击转身、硬直仍能移动、运行时重定向受击不显示或敌人挡摄像机。先核对当前引擎、消费工程、实际角色和插件源码；这里的 UE 5.8.3 案例不能替代其他版本的 API 核验。骨架、动画源及线程责任见 [跨层集成](gasp-mover-integration.md)。

## 把一次真实命中贯穿到最终表现

先定义方向语义：通常是攻击者相对受击者的来向，不是身体倒向。正面命中可以表现为向后仰；不能据此断言选中了 Back。通过实际动作确认资产映射，不凭 F/B 文件名判断。

对一次命中关联伤害/命中身份、网络角色、模拟帧和时间，记录：

`真实攻击技能 → Authority 武器 Trace/伤害 → 攻击来源、命中部位和强度 → 方向基准与分类 → 匹配及回退 → 受击复制状态 → 实际播放 Mesh/Slot → 可见根骨及身体姿态`

直接注入受击事件是下游隔离测试，不能证明真实武器提供的命中部位、来源和时序正确。优先用锁定目标与攻击者不同的侧后方攻击复现，避免正面敌人同时作为锁定目标掩盖问题。

## 1. 方向基准与匹配回退分别查

- 分别观测 Actor/UpdatedComponent、动画源 Mesh 的已求值根骨世界旋转、可见 Mesh、ControlRotation。GASP OffsetRoot 可能让身体与胶囊朝向不同；只看 ActorYaw 不足以验证玩家看到的前后左右。
- 在分类前保存实际使用的朝向基准、攻击来源、局部前/右投影与分类结果。基准按项目合同选择，核对作者前向轴和 Mesh 变换；案例中的 UEFN 源骨架使用局部 +Y，不推广为所有骨架常量，也不统一补 90°。
- 检查 `方向 × 强度 × 命中部位` 的匹配顺序。真实 Trace 可能给 Head/UpperBody/LowerBody，而人工事件只给 Any。核对具体部位精确匹配、AnyZone 同方向同强度、nearest/default 的先后及实际命中 Entry；方向条目齐全仍可能被错误回退遮蔽。强度是否允许降级由现行定义决定。
- 若项目约定 AnyZone 为部位通用兜底，应保留明确的部位专用条目优先级，再检验通用精确方向是否早于 nearest；不能为了修左右方向抹掉部位或强度语义。
- 同一布置整体旋转 90°复测，证明方向随受击者实际朝向变化，而不是按世界轴分类。

## 2. 硬直同时约束输入、模拟和朝向写入

只在本地清除移动/跳跃输入，仍可能有受击前已发送的输入、AI 寻路、锁敌组件更新和 Layered Move 在后续阶段写入运动或转向。

找到当前 Mover 后端的最终运动生成/消费边界，核验已有委托、Modifier 和 Layered Move 的执行顺序。若合同是硬直期间禁止主动移动和转向，服务器最终运动也须满足合同；保留重力、落地及明确允许的击退，不冻结整个模拟。新增回调不能覆盖其他消费者而不调用/恢复，EndPlay 清理有明确归属。回滚/重模拟须使用该模拟时刻的有效状态，不能以当前表现快照冒充历史状态。

锁敌组件可能独立写 ControlRotation、TwinStickAimRotation 或相机目标。记录这些写入路径，在保持锁定关系的前提下按硬直合同抑制相关写入，验证到期恢复及主动攻击的正常朝向行为。

## 3. 检验 OffsetRoot 与重定向的最终姿态

检查真实 AnimGraph 的全身 Slot、OffsetRootRotationMode、Steering 和后续骨骼处理。Montage 活跃可能触发 Release，使可见身体朝胶囊对齐；仅将某个模式设为 Lock 也未必保持世界朝向。

区分“保持相对 Mesh 的偏移”和“保持受击开始的世界朝向”。组件网络平滑或 Steering 仍可改变后者。逐帧比较已求值根骨世界旋转，测试整个硬直区间的最大误差，不能只比较开始/结束 ActorYaw。

确需姿态约束时，优先利用当前官方扩展点；不足时才加最小表现桥。游戏线程捕获每次新命中身份对应的朝向，动画线程只读安全快照；保持原 GASP 图顺序，限制改动到受击期间。不要把世界朝向保持做成永久 root/pelvis 偏移，也不要用它掩盖错误重定向或模拟转向。

双 Mesh 角色需确认受击实际播放在标准动画源，显示 Mesh 通过原重定向链消费；核验源 Tick、可见性裁剪、Slot 权重、播放时间和可见骨骼变化。受击绑定隐藏源不等于所有攻击都应改播该源。

## 4. 摄像机碰撞读实际对象

先识别当前相机 rig/policy 的真实通道与命中组件，再检查敌人 Capsule、可见 Mesh、装备和附属 Primitive 组件的 CDO 及运行实例。C++ 默认值改为 Ignore 后，既有蓝图可能仍保留序列化的 Block；加载、编译、保存及重新加载后的属性才是证据。

当项目明确要求敌人不阻挡相机时，只调整需要忽略的通道/组件，保留伤害 Trace 和其他碰撞语义。实际相机通道探测时必须启用待测 Actor 的碰撞，不能通过整 Actor 禁用碰撞获得假绿。近敌前后侧接近与墙体遮挡分别回归，验证构图恢复及环境防穿透。

## 5. 最小验证矩阵与报告边界

| 验证层 | 必要观测 |
|---|---|
| 数据选择 | 前后左右、实际伤害强度、Any 与真实命中部位组合的 Entry 和回退；具体部位专用条目不被通用条目遮蔽 |
| 单人真实战斗 | 实际敌人技能和武器 Trace；未锁定/锁定侧后方攻击；命中与伤害来源正确 |
| 硬直生命周期 | 连续不同方向命中、移动/跳跃、已在途的输入、Actor 和已求值根骨朝向、ControlRotation、到期恢复及正常攻击 |
| 网络 | 远端实际拥有玩家、敌人及旁观者；分别检查服务器模拟和客户端可见姿态，不以服务器朝向替代客户端观测 |
| 摄像机与渲染 | 实际通道 Trace 命中对象、带渲染受击画面、近敌与墙体对照；动画姿态和朝向最大误差 |

技能/资产异步加载时等待明确就绪条件，例如真实攻击能力已授予、玩家已拥有、动画源已初始化；使用有界超时及缺失状态诊断。固定睡眠只能节流，不能作为就绪证据。

读取报告测试数量、状态、Error/Ensure/Fatal 和 Warning；进程退出 0 或零测试不证明成功。NullRHI、注入事件、Montage 时间推进分别只有各自范围，不能代替真实 Trace、渲染和人工操作验收。Dedicated、延迟丢包、Cooked 交付及人工观感逐项标注实际覆盖，未测不写通过。

## 工具路径与适用范围

优先使用可用的 UE 原生 MCP、官方编辑器 Python/Commandlet、自动化和引擎截图；连接后读取实际工具/schema，资产修改后重新加载验证。遵守用户已明确的工具限制，不把当前会话禁用某种 UI 工具推广成所有项目禁令。

一次 RenderOffscreen 清理崩溃只说明该版本和运行配置没有完成验证。保留日志、崩溃阶段和无报告事实，改用正常渲染运行验证；不能写成该参数永久不可用，也不能把正常模式通过说成异常路径已修复。
