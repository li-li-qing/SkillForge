# 武器动画常见误诊与验证

仅在实际采用 LGF + GASP/Mover 的工程使用。来源与证据边界见 [迁移依据](migration-evidence.md)；以下诊断分支不等于每个项目已有这些缺陷。

## 装备后仍是旧姿势，跑几秒才切换

逐层观测同一个 Pawn、源 AnimInstance、世界与帧：服务器装备提交 → 公开复制 → CombatStyle 快照 → Chooser 输入 → 输出动画/数据库 → BranchIn/MM/Blend Stack 实际候选与播放时间 → 最终分层。写入 Tag、Chooser 输出有 Tag、真正播放该风格，是三种不同证据。

同时核对状态进入刷新与持续更新：哪些函数写 ChooserOutputs/ValidAnims，哪些条件才更新 BlendStackInputs，旧候选是否仍存活。读取本轮状态枚举，不把 raw state=3 固定叫循环态。重新导出改后生成图，旧图不能证明新二进制。

有延迟时检查 Start/Pivot/Refacing/Switch 等过渡的真实选择、时长与退出提前量。仅在有证据时为该风格补匹配过渡或利用现有无候选回退；不要全局滤掉空中、Traversal、其他武器，或单靠定时强刷掩盖未接上的状态。

## 全身双剑动画又叠静态持剑

先读真实层顺序、Slot、曲线来源与权重。采用逐风格姿势覆盖曲线的工程，应由实际求值姿势中的美术覆盖量控制持剑层，检查混合期间曲线、默认值、旧风格残留与线程安全。风格 Tag 表达装备状态，Chooser 输出表达某次选择；两者都不能当作“当前全身动作已覆盖双臂”的证明。

不恢复“武器 Tag + 粗移动状态压 Overlay 为零”的旧方案，也不为已有覆盖契约另造表现真值桥。采用其他分层设计的项目先读其合同，不把曲线名字或固定权重照搬。一个正确 Idle 不能替代走跑、蹲伏、起停的整套全身数据。

### 覆盖曲线与自定义 AnimNode 的落地检查

本案例使用普通浮点动画曲线 `LGame_WeaponPoseCoverage_<完整StyleTag>`，不是 Metadata 曲线。语义为美术抑制遮罩：`EffectiveAlpha = clamp(MaxAlpha,0,1) * (1 - SafeCoverage)`；曲线缺失/非有限值按 0，有限值限于 0～1。不要把它称为每根手臂精确姿势贡献、播放来源指针或 Gameplay 权威。

1. **同一次求值**：先评估 BasePose，直接读取该 PoseContext 的 Curve；完全覆盖就返回这份基础结果。不为“先探测再输出”重复 Evaluate 整条基础链，也不从上次 Chooser 结果推断当前遮罩。部分覆盖继续既有逐骨混合并保留需要的曲线/属性。
2. **线程交接**：Game Thread 写入风格前处理已有并行任务的同步；本项目使用 GetProxyOnGameThread 后同时更新单 Tag/容器。PreUpdate 取快照，Update/Evaluate 读快照；不在 AnyThread 用反射遍历 ASC/Equipment。不要把某个同步调用当作任意 UObject 都可跨线程访问的保证。
3. **钩子真的生效**：不仅检查 C++ 有 PreUpdate，还检查 HasPreUpdate、当前编译生成的 AnimBP 类的预更新节点登记及实际实例。测试新生成类，避免旧类缓存恰好掩盖登记缺失。
4. **混合边界**：检查当前 BlendStack 对缺失曲线的混合规则和相关配置。普通曲线在 BlendProfile 下不必跟每个手臂相同权重，不能用关闭曲线修复开关来换测试绿灯。观察淡入淡出而非只测 0/1 极值。
5. **退出与重建**：原地换风格不重入移动状态、收纳、无有效源、重建 AnimInstance、URO/暂停后恢复都要测；无新求值就没有新视觉，不能承诺同帧热更新。旧风格曲线不能压掉新武器的层。

若左转时手腕突然翻转，另查 BranchFilter 的起始骨、渐变深度和局部/网格空间旋转混合；不要盲目加权重、扩到 Spine/Pelvis 或改 Socket。方向与上身层的问题分别定位后，回归单剑双臂过滤不被误用。

## 锁定后左右/后退仍播前进

先确认实际按键/步态，再对照：World Intent、Actor/Control Rotation、局部方向、硬锁状态、RotationMode、Strafe 配置、Chooser 表与实际动画时间。LGF 锁定目标与样例 TargetedActor 不必是同一变量。模拟方向正确而选片错误，修选择链；胶囊正确而身体方向错，检查源片段与重定向；不要同时交换输入轴、动画名和 root 方向。

用固定相机、旋转相机、旋转角色，分别在未锁/硬锁下测试前后左右与斜向。表观“不动”先看播放时间是否前进；身体左右跨步与根轨迹方向不一致也会显得僵硬。

## 跑出去再弹回、脚滑、循环卡顿

分开观察 capsule/UpdatedComponent、源 Mesh、Root Bone、显示 Mesh。检查根运动提取/Root Lock、Offset Root Bone 模式与累计偏移、模拟是否重复消费、网络 correction，再检查时间轴。

**Root 与 Inplace 同名不证明周期配对。** 一个案例中身体 2.4s 含三个周期，Root 0.8s 只有一个；按归一化时间拼接使根速度约变成三分之一。仅用时长也不能判错：先检查骨骼运动的周期重现、Phase 接触时点、播放速率、距离与速度。

优先选同一完整来源的身体与根周期；若合成，需证明每一周期和边界对应。验证必须独立于生成算法：不能用同一插值代码重新算一遍就声称动作语义正确。保留原素材，修项目派生及生成器，避免重跑恢复旧错误。

UE 5.7 资产验证易错点：

- 官方 API 的帧数可能是帧间隔数；逐关键帧核对前确认 n 与 n+1，不把等距抽样写成全帧审查。
- PSD 的 SamplingRange=[0,0] 可以是完整循环哨兵；使用 GetEffectiveSamplingRange/IsLooping，不按两个零判空。
- BranchIn Notify 的对象全名参与 ID，duplicate 后需重绑副本数据库 ID；正式对象身份不能随意重建。
- 索引在派生缓存中重建，PSD 文件 SHA 未变不能单独否定重建；核对 IndexValid 与实际搜索。
- Phase 的极值覆盖不能代替足部接触与循环语义；重建 Phase、覆盖曲线、Notify 区间后重新加载检查。

## 预览、正式攻击与人工边界

完整攻击预览、正式 Montage/Section、命中窗口、续招窗口是不同交付。未逐击审核前保留零伤害预览，不平均切段、照搬另一武器窗口或为了全绿删除伤害断言。真实人工审核再决定帧窗、推进与握持；报告写清当前只能验收哪一层。
