# 旧维护库补充：数据回退与容量边界

2026-09-14 从旧 Replicated Suite 维护资料补充；这是设计检查方法，本轮没有运行 RU 客户端。现有具体协议与工具以本技能其他参考为准，不恢复旧资料的固定服务名和硬阈值。

## 回滚不只换代码

代码回滚与数据回滚是两个操作。新代码已写新 schema 时，旧包可能无法理解它；发布前明确支持回退、需要兼容迁移还是明确拒绝，不能把覆盖旧 ZIP 称为自动恢复。

迁移先验证旧数据与版本/预算，保留后端确实支持的可恢复状态，在内存转换和校验，再写入并做可用的读回确认。写入失败保留原证据；不把默认配置保存覆盖坏档。未来 schema 不静默降级，未知字段按 Store 的拥有权合同处理。

恢复布局、恢复一个 Feature、重置一个 Store 与清全部配置必须区分。默认值变化只影响新建/明确恢复，不覆盖玩家显式选择。备份设置容量与保留规则，不无限创建副本，也不承诺宿主不提供的原子写入/LastKnownGood。

## 容量与停用

高频 Feature 检查 Demand 所有者、调度任务、缓存/历史上限、Diff 更新和停用清理。隐藏 HUD 不等于释放采样需求。压力规模来自实际产品目标与测量，不把旧稿约 200 人或固定刷新周期推广为通用验收值。

性能修复同时测高负载启用和禁用后的资源归零，防止通过不更新数据换取速度。诊断计数有界、可关闭，避免持续构建长字符串或每个单位独立创建 Timer/闭包。

## 可恢复发布与可访问性

发布清点真实 TOC、加载顺序、最终覆盖包与删除清单；不能只检查开发目录。Preview/Beta 与 Stable 的验收条件分开，Native 时序/输入/存档未测就保持待实机。热修复不略过有关数据安全检查。

长俄文/中文、负数、大数、未知与离线状态应在实际宽度和缩放下保留语义。关键状态不用颜色单独表达；焦点/隐藏控件不能抢 gameplay 输入。分辨率样本是测试点，不是新增按分辨率写死坐标的理由。

进口报告或配置先检查结构、大小和版本，不执行载荷代码；仅解析/预览成功不等于已应用保存。支持报告最少化用户内容与身份信息，文件名过滤不能替代内容审阅。

兼容状态根据当前 Native 契约区分已验证、未知、降级与不支持；启动成功不是完整兼容证明。缺少可选价格/装备元数据只降级受影响功能并显示未知，不能伪造零值或禁用整个插件。涉及物品修改的能力必须满足本地门禁。若启动失败需恢复模式，保留最小诊断/只读恢复入口，不臆造沙箱外权限。
