# 交互与状态

## 用状态表补全操作

只列本次功能实际可能出现的状态。例如“日志中的错误定位”：

| 状态 | 用户可见内容 | 操作与焦点 |
|---|---|---|
| 没有日志/筛选无结果 | 分别说明尚无记录或当前筛选无匹配 | 可清除筛选；不把正常空集合当成加载失败 |
| 加载历史记录 | 可识别的加载提示，已有结果按需保留 | 不把加载中显示成零条结论；允许任务支持的取消 |
| 已选中错误 | 摘要、来源、可定位对象/位置 | 明确的定位动作，支持现有键盘习惯 |
| 正在定位或加载目标 | 处理状态与当前目标 | 避免重复提交；保留原选择，不能因新日志到达跳走 |
| 定位成功 | 目标在列表/预览/属性中一致可见 | 仅在用户主动发起时按设计移动焦点，并有返回日志路径 |
| 对象已删除/不可访问/操作失败 | 说明无法定位的原因和仍可查看的信息 | 保留日志上下文；提供适用的重试、复制信息或返回动作 |

每项状态还需说明动作是否可用、如何退出。未知 API 能力、数据暂缺和真实空值在内部状态与显示上都应可区分；无法提供具体错误原因时如实描述未知，不伪装成成功。

## 键盘与焦点

沿用现有 Tab/Shift+Tab、方向键、激活和取消约定；新增快捷键先查冲突。给出从对象选择到属性修改、日志定位再返回的完整路径，焦点样式可见。打开临时窗口时记录发起位置，关闭后恢复到仍然有效的控件；实时刷新、后台任务完成和新日志默认不夺取焦点。

鼠标和键盘是独立验证路径：鼠标可点不证明键盘可达，有焦点也不证明鼠标命中。不可用状态应说明原因，不能只把颜色调暗。

## 拖动和输入边界

可拖动面板区分按下、拖动、提交、取消与失去捕获。记录拖动前位置；释放按项目规则保存，取消恢复。检查移出窗口释放、切换模式、关闭面板和显示区域变化后是否清理捕获/拖动状态。编辑柄与业务按钮不能争抢同一输入。

遇到点击失效，按项目框架检查顶层窗口/遮挡 → 父子命中规则 → 控件启用状态 → 输入模式和焦点 → 事件是否到达 → 业务处理。先记录实际层级和事件证据，不把一条 UMG 规则推广到 MFC 或其他插件框架。

## 验证记录

写明实际窗口客户区、DPI/缩放、内容规模和执行动作。布局截图、键盘/鼠标操作、后台状态变化和性能测量分别记录；尚未操作应用时，这份表是检查方案，不是验收通过。
