# 布局模式

## 战斗 HUD

围绕玩家必须立即判断的事情分区：角色/目标与战斗预警保留中央视野；团队状态放在可快速扫视的稳定区域；技能冷却与对应输入靠近；伤害统计默认显示紧凑摘要，可按需展开。位置是方案起点，需在项目镜头、战斗特效和最大团队人数下检查。

为长名字、数值位数变化、死亡/离线提示预留空间。选择适合字体的稳定数值宽度；血量更新不改变行高。实时排行榜区分数据更新与显示排序：在明确时机重排，或在用户检查/选择时保持顺序，同时明确当前排序状态，避免为了稳定而无提示地显示过时排名。即时战斗信息的刷新延迟按项目要求验收，不统一限制所有面板更新频率。

可拖动 HUD 默认具有明确的正常/编辑模式。正常模式保护战斗输入；编辑模式显示拖动柄与边界。保存项目现有坐标模型所需的锚点/偏移或等价数据；切换分辨率、缩放和显示器后重新约束到可用区域。提供可访问的恢复布局入口，不能让它随面板一起移出屏幕。

## 工具工作台

对象列表 → 内容预览 → 属性编辑形成主任务链；实时日志、问题列表与任务进度辅助这条链。已有左/中/右结构时，底部可折叠日志区通常便于保持联系，但应复用已有停靠/分栏能力。

例如窗口可缩至 900×600：先确认这是窗口外框还是实际客户区，以及目标 DPI。扣除菜单、工具栏、状态栏后，为中心任务设最低可用空间，再选择缩小次要区域、折叠日志、将属性切换为现有标签页等方案。不要把四块固定宽高相加后假定一定放得下。窗格调整应尊重用户设置，同时提供恢复默认；缩小时临时折叠不必覆盖用户偏好。

错误记录携带稳定对象标识和字段/位置信息，由统一定位动作协调列表、预览和属性。控件自行猜测其他控件当前选择会造成不同步；业务模型和当前选择应有明确拥有者。

## 实时内容与配置面板

- 数据接收、存储与 UI 刷新分开，遵循当前框架的线程边界。新数据到达不重新构建整套布局、不擅自清除选中项。
- 日志在用户主动跟随末尾时才滚动到底部；用户回看时保留位置，提示新增条目并提供返回最新入口。过滤、裁剪历史和批量刷新后，用稳定 ID 或锚点恢复合理位置。
- 配置按用户任务分组，区分即时生效与应用后生效。显示修改、处理中、失败和未保存状态；关闭/取消行为遵循现有产品约定。
- 长文本、空集合和错误信息仍使用同一布局规则。颜色以外再提供文字、图标或形状，关键含义不依赖悬停提示。

这些是设计目标和待验证方案，不代表某个项目已实现。事件、批量刷新、缓存或虚拟化按测量和已有组件能力选择。

## 旧工作台资料中值得保留的扩展

2026-09-14 从 Advanced UI v4 提炼。以下只在相应任务出现时采用，不因为案例仓库规模大就强制引入完整停靠/命令面板系统。

- **诊断工作流**：摘要 → 过滤后的列表 → 一条记录的详情 → 源对象定位。错误保留稳定身份，筛选改变后不把“同一行号”当同一对象。
- **空间编辑**：地图/场景 + 图层树 + Inspector 各有职责；可见性、选择与编辑状态分开，变更由同一模型协调。
- **批量操作**：明确所选对象、范围、混合值和失败项；部分成功不显示全部完成，破坏性动作提供符合产品约定的恢复方式。
- **持久化工作区**：保存用户意图与可恢复位置；显示器消失、缩放变化、窗格移出边界时仍能访问恢复入口。临时折叠不能静默覆盖永久偏好。
- **扩展界面**：插件申请已有区域/层级/命令，避免各插件独立争 ZOrder、焦点和快捷键。没有扩展需求时不新建通用框架。
- **实时数据网格**：按稳定 ID 保留选中、展开、滚动和草稿；大集合按实际性能选择虚拟化、增量排序和有界历史。冻结显示要明确提示数据时效。

在角色/武器校准等创作界面，先检查宿主官方编辑器已有的 Socket、动画预览、变换 Gizmo 与重定向预览。确有缺口才扩展预览 UI，并明确哪个对象可编辑、变换在哪个空间、何时保存/刷新。两个角色重叠而无法独立观察时，不应要求用户靠猜偏移完成校准。
