# UI前置验证

用户只说“添加页面”时，先查产品定位、主要操作、已有风格、窗口/DPI与内容规模。技术选择由AI调研并解释，不只问用户用什么框架/布局。

新布局或关键交互：先提供信息分区、操作路径、空/加载/失败状态、窄窗口/长文本处理与必要线框/原型。需要用户审美或行为取舍时，B级先解释方案再问；A级保留该决定，继续模型/接口/现有风格内可确定的工作。不能把未经确认的新风格做成不可逆大改。

节点画布、实时列表、复杂预览等，分别确认编辑交互与运行调度的规模/更新频率；高风险先局部性能探针，不以少量静态节点证明大规模流畅，也不因某次实现失败永久禁止所有节点编辑器。

用户已经明确不要节点画布、已认可非节点工作台等项目决定应稳定沿用，除非明确变更。不要在另一项目继承这个具体禁用结论。

草图/截图证明外观，不证明点击、焦点、DPI适配或性能；真实验证与未验证分列。验证后把可复用布局方法/风险条件回写领域经验，项目风格回项目资料，个人协作方式回个人习惯。
