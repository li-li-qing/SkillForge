# 反射、模块与构建

## 声明检查

- 反射类型的声明、宏和包含关系由 UHT 处理。核对文件对应的 `.generated.h`，保持它为该头文件最后一个 include；不把手改生成文件作为修复。
- 根据真实继承和用途选择 `UCLASS`、`USTRUCT`、`UENUM`、属性与函数标记。检查当前版本支持的反射参数类型，避免把任意 C++ 模板或所有权类型直接暴露给蓝图。
- 跨模块使用的类型/函数检查 API 导出、定义所在模块、链接依赖和 Public 头文件边界；前置声明能否满足需求取决于实际使用位置。

## 蓝图调用契约

| 用途 | 应明确的接口行为 |
|---|---|
| 修改状态的操作 | 调用对象、输入校验、成功/失败输出与副作用；通常提供执行引脚 |
| 查询 | 是否只读、返回值是否可能未知/无效、求值成本；昂贵查询不因方便而随意设为 Pure |
| 异步请求 | 提交不等于完成；区分最终结果、取消、目标失效和请求身份 |
| 给蓝图实现的事件 | 实现责任、默认行为、C++ 与蓝图覆盖点及调用时机 |

沿用现有节点分类和错误反馈形式，检查受影响调用方。接口有网络行为时再确定服务器验证与客户端表现；普通本地工具不自动获得 Listen Server 约束。

## 构建命令如何产生

1. 读当前 `.uproject` 的引擎关联、模块与插件，核对已安装或源码引擎的真实版本。
2. 读关联模块的 `Build.cs`，从使用类型和符号定位依赖；公开接口涉及的依赖与仅实现所需依赖分开处理。Runtime 目标不能因一处编辑器调用而无意依赖 Editor 模块。
3. 读实际 `Target.cs` 与项目构建说明，确定 Target、平台和 Configuration。若目标文件、工具链或引擎缺失，报告具体缺项，不构造看起来可运行的旧项目命令。
4. 使用该引擎的构建入口和当前工程路径。命令参数引用按当前 shell 正确处理，包含空格的路径必须正确传递。
5. 记录实际命令、退出码及相关错误。反射变动在正常构建后，按该版本编辑器重载/重启要求检查受影响蓝图，不以热重载成功代替。

## 验收范围

UHT/编译验证接口能构建；蓝图编译验证图表调用关系；实际调用验证语义与失败反馈。三者不能互相代替。只对真正进入发布或运行目标的改动补该目标检查，不要求每个局部修改都全量打包。

符号及构建规则以当前版本源码、项目配置和 [Epic 模块说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-modules) 交叉核对。文档给出的示例 Target 不等于当前工程的 Target。
