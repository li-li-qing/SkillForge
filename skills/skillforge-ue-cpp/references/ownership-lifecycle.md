# 所有权、生命周期与异步结果

先画出本次对象的拥有者和结束条件，再选择指针。以下以 UE5 为范围，具体 API 与 GC 支持按目标版本核对。

| 需求 | 常见表达 | 使用前要确认 |
|---|---|---|
| UObject 持有者中的长期、GC 可见成员 | `UPROPERTY()` 标记的 `TObjectPtr<T>` | 外层对象/反射容器也处在 GC 可达链；仅换类型不建立这条链 |
| 非拥有缓存、可能销毁的目标 | `TWeakObjectPtr<T>` | 使用时重新取得并检查；有效不代表仍是当前界面/请求 |
| 按需加载的资源路径 | `TSoftObjectPtr<T>` | `Get()` 不会发起加载；未加载与加载失败分别处理 |
| 短时参数、已知作用域内的访问 | `T*` | 生命周期已由外部保证；不把它无条件捕获到晚到回调 |

这不是批量替换指针的规则。非 UObject 拥有者需要按自己的所有权方式管理引用；标准共享指针机制不用于替代 UObject 的 GC 管理。`AddToRoot` 涉及显式释放责任，不是回调崩溃的常规补丁。

[Epic Object Pointers（UE 5.7）](https://dev.epicgames.com/documentation/en-us/unreal-engine/object-pointers-in-unreal-engine?application_version=5.7) 是上述类型用途的版本化参考。跨线程操作还必须满足对象与 API 的线程契约，保活不能自动使 UI 更新线程安全。

## 晚到回调的完整条件

对于图标加载、后台计算或网络响应，分别检查：

1. 发起者和结果目标是否仍有效。
2. 回调线程是否允许访问目标对象。需要派发到游戏线程时，在派发后的实际更新位置再检查对象。
3. 结果是否仍属于当前请求代次、界面会话和世界。对象尚未销毁，也可能已经被复用。
4. 对应订阅或加载句柄是否应取消；取消不能替代已排队回调的保护。

可采用“发起时记录弱引用与请求代次 → 完成时按线程契约派发 → 获取对象并检查当前代次 → 更新或丢弃”的流程。具体函数名从当前版本和现有工程取得，不凭空添加某个等待或取消 API。

## 生命周期配对

| 拥有者 | 需要核对的结束边界 |
|---|---|
| Actor / Component | 对应 `EndPlay`、注销或销毁流程，按资源的实际生命周期选择 |
| UserWidget | 对象初始化与加入/离开显示层次不是同一件事；核对框架的打开/关闭与 Construct/Destruct 行为 |
| Subsystem / 普通 C++ 服务 | 实际 Deinitialize、析构或显式关闭协议，以及回调是否可以晚到 |

只清理自己拥有的绑定或句柄，避免使用全局解绑误伤其他消费者。以最新状态重新打开界面时，确认订阅恢复且没有重复动作。

## 验证

针对故障制造相关时序：完成前关闭界面、切关、销毁拥有者、连续切换请求；与正常完成路径对照。需要 GC 压力时在开发环境执行。检查无失效访问、无旧结果覆盖、无重复订阅和持续滞留；未运行这些场景时只能报告设计或静态核验。

## UMG 控件委托：绑定点与解绑点必须同层

`NativeOnInitialized` 每个控件对象**只执行一次**，`NativeDestruct` **每次销毁都执行**。把委托绑定写在前者、解绑写在后者，控件被销毁重建后就永久失联——症状是点击或回调彻底不发生，而且通常不留任何日志。同一缺陷有三种常见变形：

| 变形 | 机制 |
|---|---|
| 绑在一次性初始化，解在每次销毁 | 重建后不再执行绑定 |
| 重绑写在“指针是否变化”的分支里 | 关闭再打开时对象没变，分支被跳过，而解绑已经发生 |
| 屏幕空间 `UWidgetComponent` 隐藏时顺手关掉组件 tick | 该类型靠自身 tick 维护它在玩家屏幕图层上的挂接；关掉 tick 后“把自己摘掉”这步永不执行，表现为控件出范围仍留在屏幕上 |

审计方法：对每个控件类，列出所有 `AddDynamic`/`AddUniqueDynamic` 与 `RemoveDynamic` 所在函数，判断是否处于同一生命周期层；重点看“绑定次数 = 1”而“解绑次数 = N”的组合。重绑应放在每次都会执行的位置（如 `NativeConstruct`），并用 `AddUniqueDynamic` 保证幂等。隐藏屏幕空间控件时不要同时禁用其 tick。
