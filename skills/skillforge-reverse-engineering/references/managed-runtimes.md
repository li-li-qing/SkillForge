# 托管运行时与对象身份

## 先找到真正的程序

启动器、游戏窗口、运行时宿主和后台服务可能是不同进程。Java 游戏可能显示为 java 或 javaw；.NET、Electron、Unity Mono 与 IL2CPP 也不能仅凭窗口名判定。读取可执行路径、参数、加载模块和当前场景确定身份；记录实际 JDK/CLR、架构、GC、映射/混淆和程序集版本。

先使用可用的类型、方法、字段与对象枚举能力。类名或字段名与目标版本不符时核对实际元数据，不把另一个版本的方法签名硬套过去。程序集 token、JNI method/field ID 和裸内存偏移不是同一种地址。

## 引用、对象与地址分开

移动 GC 可以改变对象位置；容器替换元素也会使“同一个槽位”的对象身份变化。强引用延长可达性，不承诺对象物理地址不变。不要因一次数值对应就冻结裸地址，也不要把 JNI jobject 或托管句柄直接当对象起址。

JNI 的 local/global/weak global 引用有不同寿命与配对操作。`NewGlobalRef` 产生的引用用 `DeleteGlobalRef` 释放；字符串 UTF 字符缓冲的释放与引用释放是两件事。线程环境、异常状态和引用类型需各自核对。依据：[JNI 引用规则](https://docs.oracle.com/en/java/javase/21/docs/specs/jni/functions.html#global-and-local-references)与[对象引用设计](https://docs.oracle.com/en/java/javase/21/docs/specs/jni/design.html#referencing-java-objects)。

`jfieldID` 不等同于任意 JVM 通用的字段地址；GenZGC 颜色位、压缩 oop、对象头与字段布局都依赖具体实现和版本。没有对应运行时依据时，不生成固定解码公式。优先通过正确引用读取字段；确需地址快照时同时验证字段值、身份和生命周期，并标明只对本次观测有效。

## 重新解析可重建的业务路径

优先表达“当前会话 → 当前玩家/实体身份 → 容器 → 槽位 → 当前对象 → 字段”，在每次操作时重新取得可能更换的根和对象。重启后旧 PID、实例 ID、class/method/field 缓存和引用均重新核对；世界切换和类卸载也可能失效。

客户端、UI 复制值、存档和权威业务状态可能同时存在。先确认谁拥有真值；仅 UI 数字改变又回滚不证明数据类型错误。远程服务器上的权威状态不能通过改本机显示来替代。对授权本地环境也应通过稳定实体身份定位，避免修改同进程中的其他玩家或测试对象。

## 工具注入也需要验证

调用方法、加载 collector、暂停线程或获取全局引用不是无副作用读文件。先在简单自有 fixture 中验证引用清理、重复调用、退出和 GC，再进入复杂应用。崩溃落在 GC/JIT 线程可能是更早的原生写坏内存；保留原生崩溃日志和加载组件版本，不直接把故障归因于“GC 不稳定”。
