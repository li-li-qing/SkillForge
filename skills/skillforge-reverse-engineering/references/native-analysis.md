# 原生代码、地址和布局

## 地址写清空间

| 表示 | 含义与失效条件 |
|---|---|
| 文件偏移 | 磁盘字节位置；重打包/版本更换后需重算 |
| RVA | 相对模块加载映像的虚拟地址；不是文件偏移 |
| VA | 本次实际加载基址 + RVA；ASLR/重启后可能变化 |
| 堆对象地址 | 某次分配的实例位置；释放、重分配或 GC 后失效 |
| 字段偏移 | 相对某种布局的偏移；受版本、架构、packing、运行时影响 |

PE 的节内文件位置为 `PointerToRawData + RVA - VirtualAddress`，前提是属于该节且落在实际文件原始数据中；虚拟尾部、重叠节或损坏长度不能生成可写补丁位置。头部单独处理。证书等文件结构不能无条件解释为 RVA。依据：[Microsoft PE 规范](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)。

示例：节 RVA `0x2000`、原始偏移 `0x400`、目标 RVA `0x2080`，可映射时文件位置为 `0x480`；若实际加载基址为 `0x7FF600000000`，VA 为 `0x7FF600002080`。首选 ImageBase 与实际基址分开记录。

## 从伪代码回到实际契约

- 先核对处理器、位宽、端序、指令模式和 ABI。由参数使用、调用方与返回值使用共同恢复签名，不只看一次反编译输出。
- 字节加载和符号/零扩展决定数值解释；同一个偏移读成 int、float 或指针可能都有“看似合理”的值。数组索引、长度和对象身份的相关变化才是进一步证据。
- 结构体字段记录偏移、宽度、读写位置、生命周期和证据；未验证字段留空洞。相邻字段不等于同一逻辑对象，指针到达的位置也不自动是对象起点。
- 常量、vtable、导出和调用图帮助定位；尾调用、内联、优化和异常清理会改变反编译结构。关键路径回看汇编，必要时验证参数/返回值。
- 没有符号或可信源码时，语义名标为分析者命名，不称“恢复了原作者函数名”。重设类型后重新检查调用方，防止推测类型反过来污染结论。

## 稳定定位与补丁

模块加 RVA 能应对同一映像的重定位，不能保证版本更新后仍正确；AOB 需要限定模块/区域、匹配数量、指令边界和上下文。通配易变位移，不能把短常量匹配当唯一定位器。JIT 代码还可能重编译、失效或出现多个 tier。

修改前验证目标文件/模块身份与原字节；不满足就拒绝该补丁。指令改写还要核对完整指令长度、跳转范围、寄存器/栈与返回路径，不为凑字节截断指令。保存本次修改范围和恢复条件；再次启用不能重复分配钩子或覆盖已变化的代码。只在用户授权范围执行；只要求分析时交付补丁建议而不实际写入。

持久化定位至少复查重启、重新进入目标场景、对象重建和不同输入。写明测过哪些维度；一次成功没有证明跨版本稳定。
