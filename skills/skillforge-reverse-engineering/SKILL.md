# 逆向分析与证据恢复

先回答用户要知道的行为，再选择能证明它的最小分析范围。恢复的是可核实的接口、数据流与状态，不把反编译器生成的类型、变量名和控制结构当原始源码。

## 建立目标身份

记录样本哈希、来源、格式/架构、工具版本、目标模块或运行时，以及当前问题。动态分析再记录目标 PID、实际加载基址和会话代际；进程名相同不代表同一实例。能从本机和工具读到的先自行读取，未知项保持未知。

先发现已有 CLI、MCP 或分析工程。确认连接到正确项目和样本；没有连接就使用可用的只读文件分析，不能声称看到了内存、xrefs 或运行结果。用户排除的操作途径继续排除，不因换 Skill 恢复使用。

## 工作顺序

1. **定位问题**：从相关导出、字符串、调用点或字段的读写者切入；有源码/符号时先利用，不强行把问题变成无符号猜测。
2. **区分证据**：保存机器指令/字节、调用参数、返回值或可复现输入；语义命名和类型重建标“推测”，提出的补丁标“待验证”。单个导入、字符串或高熵区域不足以证明某项行为。
3. **核对地址与契约**：写明地址属于文件、模块、堆对象还是托管句柄；验证位宽、端序、调用约定、字段宽度与有效期。详见 [原生分析](references/native-analysis.md)。
4. **按需动态验证**：用能区分当前假设的一次输入变化、断点或追踪；先读取再修改，明确暂停、注入与调用目标函数本身也可能有副作用。未知或疑似恶意样本只在适当隔离环境执行，不把正常自有软件一律要求搬进恶意样本实验室。
5. **保存可恢复结果**：记录项目、样本哈希、地址空间、已确认/推测名称、覆盖范围和未解决项。补丁还要记录原字节、前置条件、恢复方式与实际验证；分析工具里的注释不等于已修改磁盘文件。

需要可重复的文件身份和 PE 地址核验时，在本技能目录运行：

```text
python scripts/probe_binary.py <样本文件> --rva 0x2080 --loaded-base 0x7FF600000000
```

工具仅只读识别及换算；不执行样本、不反编译、不判断恶意性。输出未知格式或不可映射原因时保留该结果；ELF/Mach-O 仅识别，不套用 PE 换算。

## 交付

先给已确认的结论和用户能执行的下一步，再附关键证据与限制。区分“文件已检查”“指令/类型已交叉核对”“目标已运行”“补丁已回读/功能验证”，不把结构校验或历史案例说成当前实测。

本技能自包含。CE 的扫描、MCP 与 collector 细节可在可发现时组合 `skillforge-cheat-engine`；故障根因可组合排障技能，不重复建立第二套任务流程。技能不会默认上传样本、安装依赖、启动服务或扩大修改对象。

IDA Pro、Hex-Rays、IDAPython 或 IDA MCP 的具体执行任务，可发现时优先组合 `skillforge-ida-pro`；本技能保留跨工具证据、地址与 ABI 职责。专业技能不可用时继续可完成的只读分析，不虚构其工具。
