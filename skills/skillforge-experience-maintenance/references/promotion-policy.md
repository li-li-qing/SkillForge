# 经验晋升标准

| 类型 | 足够的依据 | 不足的依据 |
|---|---|---|
| 个人明确习惯 | 用户直接确认的决定和适用范围；无相反的当前要求 | AI建议、含糊赞同被扩成额外权限 |
| 候选偏好 | 多次一致行为及来源，等待影响决策时核实 | 一次临时妥协就写永久禁止 |
| 技术机制 | 当前版本官方资料/源码支持且范围准确；运行结论另需实测 | 只凭模型记忆、一次不再报错、用户觉得不错 |
| 性能结论 | 版本、环境、负载、指标、方法、原始结果与未覆盖范围 | “用了某框架/模式所以一定快” |
| 失败经验 | 实际失败及条件；原因未知明确标注 | 将一次失败推广为整类路线不可行 |

状态区分candidate、confirmed-preference、source-verified、runtime-verified、conflicted、superseded、withdrawn。写入位置区分候选存储和正式资料；技术条目可以source-verified而运行not_run，不能伪装成实测。

记录公开决策理由，不保存隐藏推理、凭据、个人路径或无关私人内容。用户反馈可作为现场报告，不能冒充本轮已复现。不要将LAssist与其他工具未经核实合并为一个工程。

只有适用范围、来源、状态、现有规则关系和回归要求都清楚且无冲突，才可自动晋升；缺一项留候选。删除/失效旧经验保留版本关系，不通过擦掉历史隐藏错误。

对没有新知识的任务，交付“无新增可复用经验”即可，不强迫写入。维护任务结束记录哪些规则变了以及为什么；未经实际文件操作不能写“已更新共享Skills”。
