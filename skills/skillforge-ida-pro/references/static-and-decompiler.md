# 静态、反编译与数据流
## 基线与函数边界
先检查 loader、架构、指令模式、端序、重定位和自动分析。IDA 自动识别的函数边界可能漏 tail chunks、把数据识别成代码或把异常路径拆开。用入口引用、prologue/epilogue、异常/unwind 信息与实际控制流交叉检查。字符串枚举依赖编码、最小长度和分析选项；imports/exports/symbols 与程序运行行为不是等价证据。

## 调用链
每条边记录 caller_start、callsite、target、edge_kind 和证据。反向从关键函数的入口和 thunk 查询 xrefs，追踪到业务调用者；下游逐条检查 call 指令，跳转到其他函数的 tail-call 单独记录。虚调用、函数指针、导入 thunk 和动态解析要记录候选目标集合及依据。Call Graph 的空白不是无调用。CFG 看 basic blocks 和成功/失败分支；数据流追踪参数、返回值、指针别名、符号扩展、长度与生命周期。加密或压缩算法只能由操作序列/常量/测试向量综合识别。

## Hex-Rays
先 init 插件并核对所需处理器反编译器；不可用就输出汇编和失败原因。将关键条件、循环、switch、参数传递和返回路径与指令逐项对照。优化可能产生尾调用、内联、共享 epilogue、常量传播、模板实例折叠或去虚化。不能将重复伪代码直接称模板，也不能从缺失函数推断未调用。
签名由 ABI、调用现场、寄存器/栈、返回值使用共同约束；局部变量宽度与有符号性由 load/store 和扩展指令证明。结构体、类、函数语义名是分析者的候选，附置信度。疑似混淆记录具体异常（不可达边、间接分发、栈不平衡）及可能的分析器误判，不能自动执行解混淆脚本。

## 数据库可恢复修改
工作 IDB 记录变更前值、预期后值、理由与地址，先小批次；读回每项。已授权的类型更改后重新核对受影响 caller 与伪代码，避免循环证明。缓存以数据库修订号失效。工具超时先读回，不重复应用未知结果的写入。
