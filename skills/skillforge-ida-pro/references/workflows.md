# 四条实际工作流
所有步骤共享同一证据表，不重复启动总入口。没有目标、IDA 或必要授权时隔离依赖步骤，继续可完成的只读检查。

## 陌生 DLL（也适用于调整后的 ELF SO）
1. 保存来源、大小、SHA-256；复用可用的通用逆向 probe_binary.py。PE 的 Machine、optional-header magic 与 sections 交叉核对；ELF 看 class、endianness、e_machine 和 program headers，不能套 PE RVA。
2. 编译器识别保留证据（RTTI、异常表、导入、符号等）及不确定性；单条字符串不确定工具链。
3. 用工作 IDB 加载正确 loader/processor。GUI 中核对 Segments/Functions/Imports/Exports/Strings 窗口与数据库输入；自动分析完成后再统计。加载错误先纠正，不能依赖错误边界。
4. 汇总 entry、imports/exports、函数和字符串数量。记录枚举设置与覆盖率，strings 统计不代表全部编码的文本。
5. 从用户问题相关导出、字符串及 API xrefs 排出有限候选。建立上游调用者与下游直接调用、间接调用未知边。
6. 只反编译关键函数；核对分支、参数、返回值及全局访问。记录候选类型。
7. 必要时隔离调试一次可区分假设的输入。报告引用原始证据路径、地址与观察条件。

## 单函数/字符串定位
定位命中字符串的实际地址与编码 → xrefs（包含数据引用）→ 包含该地址的函数/跳板 → 函数 chunks 和边界 → 汇编及伪代码 → ABI 参数/返回值 → callers → callees → 关键全局/表 → 待验证假设。
字符串可能先引用到指针表；向上追踪数据引用后才到代码。多个命中保留候选，不任取第一个。反向 caller 需按函数起点去重但保存每个 call-site。下游不是所有 code xrefs：排除内部跳转，识别 call 和尾跳，间接边标未知。

## C++ 类
找构造/析构 → 核对 RTTI → 构造中虚表写入 → this 调整 → 多个函数的成员读写 → 按偏移/宽度合并候选 → 保留空洞 → 继承/子对象 → 建候选头文件 → 独立读写/大小/分配证据验证。见类恢复案例。类型应用是另一项有授权的 IDB 修改，不将候选布局直接确认为原始类。

## UE
确定引擎版本、平台、构建配置、符号/PDB/源码/LTO → 引擎模块与业务模块候选 → UHT/注册与反射信息 → UObject/UClass/UStruct → 目标函数及成员 → RPC 标记和网络调用路径 → 属性复制注册/条件 → 序列化 → 必要的已授权资产证据 → 报告。
没有完整反射数据时转用构造/虚表、调用关系、符号和版本匹配源码；不能据此断言“不存在类/RPC”。报告回答类归属、类型、偏移、RPC/复制、模块、原生/Blueprint，未知项保留。
