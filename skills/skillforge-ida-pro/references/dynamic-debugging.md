# 动态验证
## 建立实验
记录 debugger backend、目标路径/hash/PID/启动参数、模块实际基址、ASLR、权限、环境与输入。未知样本使用隔离环境；attach、暂停、调用目标函数均有副作用。只使用已授权目标，不把静态分析授权扩展为在线作弊、注入或绕过保护。
先设计能区分两个假设的最小输入。例如成员偏移 0x10 是否为目标指针：在分配/构造结束后暂停，读取对象内存及写入指令，改变受控输入，检查同一对象身份与生命周期。

## 操作步骤
选择 IDA 支持的当前 debugger，核对本地/远程进程和位宽。启动或附加前核对进程身份。
软件断点会改变执行内存，硬件断点受数量、长度、对齐和后端限制；条件断点表达式及求值上下文以当前后端为准。记录新增断点，停止时只移除本会话断点。
在模块加载后把静态 RVA 转成实际 VA；确认指令相同再下断点。停止事件后读寄存器、栈、内存和调用栈；optimized/unwind 缺失时调用栈可能不完整。Windows x64 入口 RCX/RDX/R8/R9 是整数/指针参数线索，浮点、聚合返回、成员 this 和其他 ABI 必须另核对。
单步跨越可能触发系统调用或线程竞态；不要把一次暂停状态泛化为全部执行。写下暂停原因、线程、PC、输入、观察与反例。脚本使用 ida_dbg 前查事件/请求队列契约，异步请求提交不等于完成。

## 交叉验证
静态：指令在地址 A 读取 this+offset。
动态：在给定输入、PID、线程、时间，PC=A 时读取值 V。
结论：该实例此次路径符合候选字段；不自动升级为所有构建共用布局。
失败、未命中断点与命中截断单独报告；检查 ASLR/优化/路径而非直接宣告函数不存在。恢复暂停状态、只清理自建资源，记录异常结束时尚未恢复的内容。
