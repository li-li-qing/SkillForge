## BP-K01：首次打开 Accessed None，重开恢复

| 字段 | 内容 |
|---|---|
| 状态 | 从项目初始化约束构造的代表案例，未取得真实资产复现 |
| 症状与条件 | Widget 在 Construct 获取背包引用，首次来源未就绪，重开时可用 |
| 版本 | UE5；UI 框架与创建路径需现场确认 |
| 证据 | 错误位置、创建顺序、来源类型和数据就绪事件是必须补充的现场证据；当前只有案例描述 |
| 原因 | 尚不能唯一确定；候选为对象来源、拥有者或初始化时序，而非已证实“缺少 0.2 秒等待” |
| 修复方向 | 显式来源初始化、有效/无效分支、当前快照与变化订阅；清理旧来源并使重复调用安全 |
| 验证结果 | 仅文本方案可评测；真实资产编译、保存和首次/重复打开回归未执行 |

## BP-K02：第三方技能误述 Construction Script

| 字段 | 内容 |
|---|---|
| 状态 | 本机源码已核验，运行场景未执行 |
| 症状与条件 | 把运行期 UI 绑定放在 Construction Script，并假定它只在编辑器执行且只绑定一次 |
| 版本 | UE 5.7.4，CL 51494982 |
| 证据 | `Actor.cpp::FinishSpawning` → `ActorConstruction.cpp::ExecuteConstruction` → 用户构造脚本；参见 [初始化与通信](initialization-communication.md) 中的引擎相对路径 |
| 原因 | 混淆编辑器重建、运行期生成和加载路径；社区技能的绝对说法不是引擎契约 |
| 修复方向 | 可重建构造状态与运行期外部数据绑定分开，按实际就绪与会话生命周期接入 |
| 验证结果 | 调用路径确认；仍需实际生成、编辑器重建以及项目所需加载/打包场景验证 |

## BP-K03：把普通 Panel 嵌套误判为 BindWidget 不支持

| 字段 | 内容 |
|---|---|
| 状态 | 本机源码已核验，未创建复现蓝图 |
| 症状与条件 | 指针为空时，旧 LGF 笔记将原因归为“不支持直接子之外的控件” |
| 版本 | UE 5.7.4 |
| 证据 | `Engine/Source/Runtime/UMG/Private/WidgetTree.cpp` 的 `ForEachWidget` 遍历普通容器后代；`WidgetBlueprintGeneratedClass.cpp` 的 `InitializeWidgetStatic` 按名称赋值属性 |
| 原因 | 同一 WidgetTree 的普通嵌套不等于另一个 UserWidget 的内部树；指针为空还要查名称、类型、父类、实例与初始化阶段 |
| 修复方向 | 查实际树与绑定契约，不先添加按名称查找的兜底来掩盖错误 |
| 验证结果 | 遍历与赋值路径已确认；具体资产绑定失败尚未复现或修复 |
