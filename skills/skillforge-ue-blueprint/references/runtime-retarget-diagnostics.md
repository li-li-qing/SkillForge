# 运行时重定向：面颈错位与脚底悬空

适用于示例角色单独播放正常、接入玩家后异常的情况。示例蓝图和玩家 Pawn 可能使用不同动画源、组件绑定和 Retargeter；先找两者真正分叉的位置，不把示例正常等同于玩家运行链正确。

## 先还原两条真实运行链

在运行实例和类默认对象分别记录：Pawn、组件层级及相对变换、实际可见 SkeletalMesh、Skeleton、AnimBP/PostProcess、动画源 Mesh、用于选择 Retargeter 的 Tag/映射和最终 Retargeter 路径。`SK_...` 可能是 Skeleton，`SKM_...` 可能是 SkeletalMesh；以资产类型和引用验证，不凭前缀判断。

对照示例蓝图的独立 Sequence/Montage、Leader Pose、Copy Pose、Live Link 与初始化节点。只有玩家链真正依赖同一个驱动时，才考虑复制对应设置。隐藏动画源、可见目标、权威 Trace 可以是三种不同职责；检查源是否继续更新姿势、目标是否取对源、Tick 顺序/可见性/LOD/URO 是否让远端丢姿势。若只有更换外观，保留已有 Gameplay/移动/判伤来源。

建议先输出一张对照表：`示例 BP → 姿势来源 → Body/Face 驱动 → 可见网格` 与 `玩家 Pawn → 主 AnimBP → Runtime Retarget → 可见网格`，每一栏写实际对象路径和证据，未读到的节点标未知。

## 面颈：用局部变换定位错误层

MetaHuman 式 Body/Face 分离时，不能只比较头和脸的世界位置。选当前骨架中 Face 分支的根骨及其 Body 侧 neck/head 父骨，记录目标参考姿势与运行姿势的**父骨局部**平移/旋转，并与示例的绑定关系对照。先排除 Face 组件相对变换、Leader/Copy Pose 源错、动画源 Skeleton 不一致、目标 Retarget Root/链映射错误。

若证据表明身体运动已正确，而 Retargeter 改坏了目标 Face 分支相对于 neck/head 的参考局部姿势，才在项目派生的目标 Retargeter 中恢复相应根骨局部变换，并确认其子骨按预期传播。具体使用 Pin Bones、Copy Bone 或其他操作取决于目标版本的操作栈与资产结构；检查它实际运行在骨架链求值的哪个阶段。不要靠全局移动 Face 组件掩盖仅在动态姿势下暴露的局部错误。站立和至少一段运动姿势都要复测面颈连续性。

## 脚底：区分关节、网格几何和地面

固定同一帧及地面点，分别取 Capsule 底、地面碰撞命中、隐藏源与可见目标的 root/pelvis/foot/ball 世界坐标、脚 IK Goal，以及鞋底相对 foot/ball 的参考几何。记录单位和坐标系。两套脚骨高度接近而鞋底悬空，可能是鞋底到 ball 的模型几何差异；不能据此直接下移 Capsule。若只用整网格最低顶点估算鞋底，应标明它不是蒙皮后逐顶点地面接触证据。

对照源/目标参考骨盆高度、腿长、目标 IK 链可达范围和当前运动姿势。降低 IK Goal 后若腿已经伸直，继续加 Goal 偏移可能不再有效；先确认限制，再评估有依据的骨盆/根姿势校正与脚目标修正。操作栈中 IK Goal 修正应进入实际 IK 求解前，面部目标修正应处于不会被后续步骤覆盖的位置；按当前引擎实现与运行输出确认顺序。偏移数值由具体模型测量得出，不能复用别的角色数值，也不能靠 Capsule 高度或整个可见 Mesh 的 Z 偏移遮盖错误。改骨盆后复测膝盖、上身、手腕、握持和可见武器与权威 Trace 的对齐。

## 编辑器写入与验收边界

修改前备份准确的项目派生资产，不覆盖示例/第三方原件；通过目标版本的官方编辑器 API 或 UI 编辑。脚本修改 Retargeter 的嵌套设置数组时，先确认 `get_editor_property` 返回的是可直接变更的引用还是值拷贝；必要时把改过的元素写回数组，再把数组写回设置对象并调用设置 API。保存后独立进程重新加载、读取关键操作及数值，避免只验证当前 Python 对象或编辑器缓存。

静态加载、骨骼数值采样、有渲染 PIE、移动/坡地、LOD、装备握持与服务器轨迹、Host/Remote/JIP、性能及人工外观确认分别记录。命令行工具若因另一配置错误返回非零，只能陈述已读回的局部证据及整体验证失败，不能把局部断言写成整场通过。退出临时调试连接时恢复项目原有服务和编辑器设置。
