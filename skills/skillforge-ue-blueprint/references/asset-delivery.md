# 资产操作与交付

## 按能力选择动作

| 实际能力 | 可交付结果 | 仍需补充的证据 |
|---|---|---|
| 只有文本/截图 | 节点与参数说明、已见内容分析 | 实际图读取、修改、编译、保存和运行 |
| 能解析资产，不能可靠写回 | 结构与引用检查、精确修改建议 | 编辑器或经验证工具执行修改 |
| 能编辑、编译、保存 | 图与包的真实改动、对应编译和保存结果 | 重新读取验证及相关运行行为 |
| 同时能运行测试 | 上述结果加 PIE/Standalone 等场景记录 | 未覆盖的平台、网络角色或打包目标 |

检测当前工具提供的能力，不预设某个 MCP、插件或 Agent 专属工具必定存在。解析器有版本限制时先确认格式支持。不要把保存时间戳、索引缓存或某个 API 返回 true 当作全部验收。

## 修改前后

1. 定位准确资产包、父类、现有图、变量、组件、事件签名与调用方；保留可恢复的修改前状态。
2. 实施后读回关键节点、默认值、Target 和执行/数据引脚，确认修改落在目标资产，不是相似名称的另一份资产。
3. 编译受影响蓝图和调用方，处理实际错误；保存明确列出的资产包，确认保存结果与位置。
4. 工具支持时从磁盘重新加载或在新会话重新打开，核对关键图及编译结果。若重载会影响未保存工作，先完成当前授权范围的保存并保留其他工作；不能直接丢弃无关编辑。
5. 根据改动跑首次进入、重复操作、无效来源或延迟就绪等相关场景。编译与保存通过不能替代行为验证。

## 文本模式的可执行说明

说明需要足够让用户照着接线，但不猜已有节点名称。建议按每个改动列：

- 目标资产/图：已确认的名称；未知时给出可识别的父类、功能入口和查找条件。
- 变量：新建或修改、类型、默认值、来源与谁赋值。
- 节点：内置节点类型或明确标识的自定义函数/事件、作用对象、关键参数。
- 连线：执行线顺序与条件分支；数据从哪个输出接到哪个输入，Target 是否与类型一致。
- 失败/未就绪：显示或返回什么，何时重试/再次进入，怎样清理。
- 验证：编译对象、保存包、实际操作和可观察结果；没有执行的阶段明确标记。

简单的单节点问题只需对应的短说明，不强制输出整份架构文档。文本流程和图示均是操作说明，不能当作已导入的资产。
