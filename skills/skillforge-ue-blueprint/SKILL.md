# UE 蓝图开发

先确定正在操作哪个资产和运行实例，再设计节点、数据与生命周期。根据当前工具能力交付真实改动或可执行说明。

## 识别上下文和能力

- 从工程或用户材料确认引擎版本、目标资产、父类、图类型、调用方与所属玩家/世界；区分类默认值、放置实例与运行实例。
- 能读取图时检查实际变量、节点、连线、组件与事件签名。工具摘要、缓存索引或截图只代表其可见范围；未读到的资产内容保持未知。
- 分别确认能否读图、改图、编译、保存、重新加载和运行。普通文件写入能力不等于安全修改 `.uasset`；无可靠资产工具时提供节点说明，不尝试猜测二进制结构。

## 组织逻辑

1. 明确状态由谁拥有、谁初始化、谁可以修改和谁只显示。复用项目现有组件/接口，不为一个界面复制第二份业务真值。
2. 按用途选择函数、事件、宏或接口。需要返回结果和可复用逻辑时优先明确函数契约；延迟操作放在实际支持的执行环境。不要为简化连线把全部流程挤进 Level Blueprint。
3. 变量写清类型、默认值、实例来源与有效条件；对象引用的有效性、类型匹配与数据就绪是不同检查。Cast 不能代替创建对象或等待初始化。
4. 直接引用适用于明确持有的协作者；接口表达调用契约；Event Dispatcher 表达通知。根据项目的所有权和耦合选择，不规定所有通信都用同一方式。
5. 对运行时依赖采用明确的就绪/更新入口。不要假定 BeginPlay、Construct 或一次 Delay 能证明其他对象已准备好。重复调用、关闭重开、Pawn 更换和旧来源解绑须与本次功能的生命周期一致。

Construction Script 可以因编辑器重建和运行期 Actor 生成而执行；不能概括为“只在编辑器”或“恰好一次”。需要运行期玩家/背包数据的 UI 初始化与可重建的构造逻辑分开。版本证据见 [初始化与通信](references/initialization-communication.md)。

## 按需参考

- Accessed None、Cast 失败、初始化、重复绑定：读 [初始化与通信](references/initialization-communication.md)。
- 工具能否实际改图、如何给节点说明和验收保存：读 [资产操作与交付](references/asset-delivery.md)。

涉及布局时可组合 UI 技能，涉及 C++ 接口时可组合 C++ 技能；缺少其他技能不阻断本技能自身工作。

## 验证与交付

有编辑器工具时，按实际能力检查改后图、受影响蓝图编译、目标包保存和重新读取；涉及运行行为时再跑相关场景。工具返回成功、文件变动和 PIE 正确分别是不同证据。

只有文本能力时，给出资产定位、需要新建或修改的变量/函数、节点类型、Target、关键引脚、执行线/数据线及失败分支，标明示例自定义名称，并附验证步骤。没有执行的资产读取、保存、编译与运行不得写成已经完成。
