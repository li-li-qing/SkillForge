# Cheat Engine 与动态内存实战

目标是找到可验证的业务状态及其访问方式。数值、裸地址、对象身份和快捷栏位置是不同的东西；一次搜中不等于找到了跨重启的基址。

## 先确认正在使用什么

核对 CE 可执行文件路径/版本、目标 PID/路径和窗口、目标位宽、游戏/运行时版本，以及已有 MCP 插件与 collector。多个版本并存时以运行中的实例为准；错误目录中的缺文件不能靠向旧版随意复制组件解决。

用户明确排除的 Computer Use 或其他途径不再使用。优先已连接的 MCP、可用 API/CLI 与文件检查；需要用户手动操作时给出当前版本的菜单/命令及观察点。已经授权的同一操作不重复索要确认，但仍遵守当前工具自身的约束。

## 读取和修改的闭环

1. **只读确认**：关联当前目标与业务对象，记录类型、宽度、值、身份及有效期；选择真正拥有状态的本地对象，区分 UI/客户端复制值。
2. **建立因果**：通过一组用户可控的值变化或类型/字段证据筛选，不能把所有“等于 16”的位置一起改写。
3. **重新定位**：写前重取当前根、槽位和对象，检查会话/版本、字段及原值。对象变化或身份不符就停止该次写入。
4. **最小写入**：在已授权范围修改正确宽度的字段，尊重对象实际取值约束；记录原值、结果和恢复条件。不默认冻结、补丁、钩子或加载驱动。
5. **核对结果**：分别记录内存读回与用户可见/业务行为。写后回滚要查权威副本和正常更新链；超时效果未知先查询，不盲目重放。

## 可复用脚本的契约

加载默认只读。提供明确的读取/修改入口，参数注明槽位索引与范围。重复加载不会叠加 timer/hook 或复用失效引用；会话、世界和目标变化后使旧状态失效。错误信息指出版本、目标或缺失能力，不能只报告一个旧路径下的缺文件。

交付要讲清启动哪个 CE、附加哪个当前进程、运行哪条命令、预期看到什么、何时重载；打印的地址快照标明有效期。没有验证到稳定定位时直说，不用旧地址包装成可重用基址。

本技能自包含，可与通用逆向或排障技能按需组合。只处理用户有权修改的本地目标；在线服务、他人状态与反作弊绕过不因用户给“最高权限”自动进入范围。
