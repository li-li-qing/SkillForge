# Minecraft / CE Java 已核实案例

记录日期：2026-11-08；运行试验发生在本次补充技能前的同一会话。此处复核了保存的验证摘要、Lua 脚本和 collector 源码；没有在本轮重启游戏重跑该试验，也未打包游戏、上游源码或用户脚本。

## 条件

Minecraft Java 1.21.1、NeoForge 21.1.219、Microsoft JDK 21.0.7+6、x64 GenZGC（UseZGC + ZGenerational），CE 7.7.0.10621。针对用户自己的本地集成服务器玩家；脚本需要该环境可访问的类/字段/方法映射。不能外推为所有 Minecraft、远程服务器、JDK 或 collector 的通用接口。

本地服务器可能含多个玩家，仍以本地玩家 UUID 匹配服务器玩家，不选玩家列表第一项。已允许修改自己的状态不意味着可修改其他玩家。

## 访问方式

每次操作从当前 Minecraft 实例取得当前本地玩家和本地集成服务器，以本地玩家 UUID 找到对应 ServerPlayer，再取 inventory、当前槽位及 ItemStack；通过实际字段读取/写入 count。快捷栏第一格在该版本接口中是索引 0，0..8 对应九格；不是任意容器 API 的统一约定。

最初仅允许 iron_ingot 的脚本对 raw_iron 无变化，属于物品条件不符；换栈、拆分和 GC 还可使对象/地址失效。后续访问器支持当前物品，读取实际最大堆叠数并在写前复查身份。地址打印是快照，不是固定基址；此例的字段偏移和 ZGC 解码没有晋升成通用规则。

## 原生错误与历史验证

collector 的字符串结果在已提升为 global 引用后错误调用 DeleteLocalRef；修复为与实际引用类型配对的 DeleteGlobalRef。独立 fixture 保留了同一 JDK/GenZGC，分配全局引用、释放部分槽位、用字符串返回复用，再触发 GC：

| 条件 | 已保存结果 |
|---|---|
| 未修复 collector | 25 个仍存活引用被破坏；ZWorkerYoung#0 崩溃；退出码 1 |
| 修复 collector | 1000 次字符串调用、11 次 GC；0 个损坏引用；退出码 0 |
| fixture 字段读写 | 26 → 64 → 26 读回 |
| 重启后的真实游戏检查 | 读到 raw_iron 数量 16；16 → 16 同值检查通过；超过实际上限 64 的请求被拒绝 |

此前用户确认过 iron_ingot 从 4 改到 64；该结果与修复后游戏同值检查是不同验证，不能混称“修复后已实测所有物品 16 → 64”。保存摘要不足以独立复核原试验全轨迹；未证明跨其他环境或长时间无故障。
