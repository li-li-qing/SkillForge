# 环境、版本与 MCP

## 识别实际程序

从进程可执行路径与版本判断当前 CE，不靠快捷方式名称。记录 CE PID 与被调试目标 PID，两者不能混用。版本不匹配、缺 collector 源码、插件未加载、目标未附加分别处理；不要用管理员权限替代这些检查。

找不到 java.exe 时，先列出真实进程及路径/窗口。CE 的 Applications/Windows 列表可能显示游戏标题，Processes 列表才更适合按 java/javaw 与 PID 查找；不保证每种安装都叫 java.exe。重启后重新核对 PID，多个 Java 进程用启动路径和参数区分，不选列表第一项。

Lua 使用 `getAutorunPath()` 时，路径属于执行它的那个 CE。若报错指向旧版本，先切到包含正确组件的安装；不能因为目标游戏相同就认为两个 CE 共享 Java 支持。

## CheatEngine.Mcp 的连接边界

以下只描述核对过的构建族，具体名字和参数读当前 schema：插件运行在 CE 内，stdio gateway 发现实例并按显式 `instanceId` 路由。gateway 在线不代表 CE 在线，MCP Enabled 不代表目标已附加。

先 `instance_list`，再对所选实例读取 runtime 信息与概览，核对当前目标后再使用进程工具。实例重启/插件重新启用后重新发现 ID；发现不完整时不要判定实例不存在。按当前工具要求读取工作流资源，切换目标前处理该会话保留的资源。

任务轮询沿用 job ID/序列号，不反复发起扫描；返回 `hostEffect=started/unknown` 或超时先查看实际状态。capability_disabled 表示能力被禁用，不另走 Lua 绕过工具限制。

来源：[CheatEngine.Mcp 固定提交 README](https://github.com/CheatEngineNet/CheatEngine.Mcp/blob/bcce6ca79cb578123ea32a8c419348a9067ce8ed/README.md)。这是源码快照，不保证某个发行 ZIP 具有所有列出的功能；当前工具 schema 与该发行说明优先。

## 安装与故障分类

优先检查已安装版本、插件/网关是否来自同一构建、位宽、用户身份和该发行要求的运行时。只安装实际缺失的依赖；不要从旧经验断言所有 CE 插件都要求同一 .NET 大版本。需要修改宿主配置时先读原文件，只调整必要字段并按其恢复能力保护原配置。

只使用已核对的上游发行/文档，校验哈希和签名的可用信息；签名存在不替代来源核对，也不把下载器包装当成所需安装载荷。卸载旧版时按用户指定版本定位，检查共享注册、文件关联和当前版本是否受影响。

客户端本会话尚未发现新工具时，先区分“配置已保存”和“工具已加载”。只能在已授权且不绕过能力限制的情况下使用该服务支持的标准连接方式；不承诺任意宿主能热加载配置，也不声称已完成没有实际连接证据的操作。
