# MFC → Qt：迁移行为，不做 API 字面替换

## 当前任务的前提

用户已决定使用 Qt；先核实当前迁移阶段，不重复展开 MFC/Qt 选型辩论。没有当前 Qt 工程时输出迁移设计与待核项，不声称已经适配实际类、CMake 或 DLL。

保留可用业务核心、算法、协议、持久化样本和测试。把旧 MFC 界面当行为证据，不把它的自绘层、遍历模型、所有权错误一并翻译成 Qt。旧框架技能仅帮助读旧实现。

## 概念对照，不是机械替换表

| 旧实现线索 | Qt 侧需要重新确定的契约 |
|---|---|
| 消息映射与 ON_COMMAND | QAction/控件意图汇入同一应用命令 |
| ON_UPDATE_COMMAND_UI | 从业务真值投影 enabled/checked，服务侧仍验证 |
| DDX/DDV、UpdateData | 输入草稿、输入/业务校验、显式提交与外部刷新冲突 |
| WM_APP payload | 拥有关系明确的 queued 值消息与代际检查 |
| Doc/View | 独立业务数据与 Qt model/view 投影；不必保留同名类树 |
| HWND/CWnd wrapper | QObject/Widget parent 与平台句柄分别管理 |
| CString/宽窄字符串 | 按实际编码边界转换，禁止一口气替换全部核心值类型 |
| WM_TIMER/工作线程 | QTimer 只触发/节流，耗时任务与固定 STA 各守线程契约 |
| 原自绘编辑框 | 优先标准 QLineEdit，验证输入法和草稿，不复刻旧分层 bug |

## 推荐迁移切片

每片独立验收，步骤不是批准整库重写的授权：

1. **基线留存**：记录可运行旧版、真实配置样本、主要交互、错误语义、现有测试及未通过项；只在安全位置复制测试数据。
2. **Qt 壳与构建**：最小入口、日志与错误出口；不同时升级全部依赖/位宽/协议。普通单进程应用采用一个明确主事件循环，不把 AfxWinMain 与 QApplication 两套主循环硬塞一起。
3. **代表性页面**：选择一个有输入、有列表、有异步状态的切片，而非只做静态首页。接现有 service/adapter，验证输入、取消与关闭。
4. **迁移同类页面**：复用验证过的 Qt 控件与 presentation 契约；更新共享基础设施时检查全部消费者，不只测试新页面。
5. **替换入口并回归**：验证旧配置、异常路径、部署；保留可回滚版本或迁移开关，直到实际发布基线稳定。
6. **清理旧依赖**：确认没有调用方后再移除 MFC UI/资源/构建配置，不因“已经换 Qt”删除仍工作的引擎。

特殊嵌入/过渡共存方案需另写事件循环、原生窗口和寿命设计；历史 QtWinMigrate 示例不是当代项目的即插即用保证。

## 功能兼容矩阵

每个功能写：旧行为、Qt 目标行为、核心复用、UI 变化、存档影响、成功/失败/取消/关闭验收、回滚点。名称相同不代表实现等价；任务从“接受”到“完成”的语义不能在迁移中悄悄改变。

Qt UI 不应直接接管本来由引擎维护的 SessionPool、输入账本、目标解析或 COM 宿主状态。实际项目有这些职责时沿用；没有当前源码证据不假设固定类名和容量。

## 数据和回滚

先用旧样本验证新读取，不自动覆盖用户唯一存档。区分窗口布局偏好和业务任务文件；迁移器声明 source/target schema、备份、未知字段和失败策略。

回滚能力需要格式证据：新程序写出旧程序不认识的格式时，不能只切回旧 EXE 就宣称可回滚。使用保留旧文件、显式新格式或已验证双向转换；不要为“兼容”悄悄丢弃字段。

## 完成标准

完成一片需要真实 UI 行为与 service 契约通过，不是所有类从 CWnd 改名 QWidget。完整迁移还需实际目标平台构建、关闭/取消、旧档、IME/DPI、热键、SDK 与干净环境部署的证据。

本 Skill 当前仅交付规则，没有迁移 LCot 的产品代码。任何接手 Agent 必须重新读取当前工程，报告已完成和未完成范围。
