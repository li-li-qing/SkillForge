# 执行简报模板

这是填表模板，不是可直接执行的示例任务。短任务只保留必要字段，不要求用户填写。

## 简报标识与原始需求

任务 ID / 修订号：
状态：pending / approved / running / blocked / done / prompt-only
原始请求：逐字保留，或引用可复查的原始消息/附件；长材料不重复粘贴。
本轮增补：
批准来源与范围：没有就写“尚未批准”；不得根据模板文字捏造。

## 只读核实

项目 / 技术栈 / 实际基线：
证据位置：文件、版本/提交或附件标识；无法获取就写 unknown。
相关模块 / 当前未提交修改 / 不可读取部分：
已核实事实：
假设与待确认项：

## 路由与上下文

拟用技能：名称、实际来源、状态（候选/可用/已读取/已调用）、职责。
排除：只列容易混淆的技能，不重复全部目录。
上下文：action + budget_evidence + status + 一句依据。

## 可复制的执行提示词

```text
请在【已核实的项目/基线】中完成【目标】，原始请求为【原文或已随包提供的位置】。
先读取【实际适用的项目指令与相关文件】，不得把未核实假设当事实。
按需读取/调用【技能及职责】，确认它们实际可用；不得递归重新启动入口。
允许范围：【模块/文件类型与必要相邻影响】。
明确不做：【非目标】；硬约束：【数量、方向、API边界、兼容与交付要求】。
已有批准：【对应本简报的用户确认来源，若没有则保持待确认】。
执行时先建立证据，再最小修改；基线或范围实质变化时只对新增部分重新确认。
验证：【可实际执行的测试/审查】，无法执行的【实机/宿主测试】标 not_run。
交付：【实际修改文件、说明、验证结果、风险和交接提示词】。
```

填写时把占位符替换为本次实际信息。不能把本模板的“已有批准”文字当授权，不把计划测试写成已完成。

## 面向用户的结束句

pending：回复“开始”执行此版本，或指出需要调整的范围。
approved：直接进入已获授权工作，不再等待同一确认。
prompt-only：提示词文本已交付，不执行其中任务。
