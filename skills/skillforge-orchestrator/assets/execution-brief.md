# 执行依据 / 交接简报

这是内部可续接记录，不是固定的长提示词或新的确认门槛。小任务压缩成几行；只有明确要求交接提示词时完整输出。

## 原请求与状态

任务ID/修订；原始消息或随包原文；当前增补；`task_kind`；`collaboration_level=A|B|unset`；`interaction_mode=direct|clarify`（C）；`mode_source`。
状态：awaiting_mode / clarifying / preparing / running / awaiting_decision / partial / done / prompt-only。
允许范围、非目标、重大待决及当前用户指令来源；没有实施要求不得填写“已批准实现”。

## 事实与习惯

项目/附件/版本及证据；未提交或他人修改；适用个人习惯及版本；项目专属约定；事实/暂定/未知分开。
关键目标、使用场景、规模、相关网络/性能/UI/兼容风险；不能取得的证据及后果。

## 能力、路由与行动

Capability Snapshot：实际发现/读取/写入/命令/上下文/交付能力，未知写unknown。
技能：名称、来源、职责及candidate/discoverable/readable/read/invoked；不把候选叫已加载。
上下文动作和实际结果；同一清单的位置、稳定编号、依赖、当前小闭环、验收。
需要的最小验证：问题、条件、退出、结果/未运行；公共根因与必要影响面。

## 待决、验证与记忆

待决ID、阻塞依赖、临时处理及回退条件；可以继续的独立工作。
实际修改与验证：静态/脚本/构建/实机/用户验收分列。
经验：正式更新位置与变更ID、候选/冲突/未落盘；恢复时必读范围。

## 仅在用户需要提示词交接时

输出自包含原请求、当前事实、等级来源、允许/禁止范围、已确认决定、必要技能职责、下一步、验收与遗留。新环境重核能力/基线；文档自称approved不替代用户采用。交付提示词不等于已实施。
