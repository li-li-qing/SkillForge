# skillforge-orchestrator 0.3.0

共享个人习惯、项目依据与按需技能的统一入口。核心不绑定Agent、安装路径、命令或固定叶子名单；没有原生技能能力时可据实际权限读取文件使用。

## 日常入口

提出任务即可。未指定入口时提供 A/B/C：A 由 AI 在既定边界内自主推进；B 由人工指挥、AI 调查和执行，方案、技术栈和未明确的功能细节先询问并等待确认；C 从需要的功能出发，每轮围绕一个核心问题给出选项、优缺点、适用情况和推荐，暂不实施。

同一任务选定后沿用；直接说“这次A级”不再问。等级不替代任务性质：“A级，只分析”不改产品代码；明确实施且已选级就不因长提示词或清单再等一次“开始”。

先读工程、个人习惯和适用技能，前置判断技术/规模/UI/性能风险；必要时局部验证。AI负责共同根因和关联回归，不能只修表面。完成后主动记录可复用经验，核对后更新真实共享源，冲突先保留。

验证只覆盖本次改动的实际风险；B 模式下的画面、视频、动画观感和交互体验，给出操作步骤与预期，由用户实际验收。已使用 Git/P4 的工程不反复备份；个人 Git 项目优先 main，P4 按完整功能段组织 Pending CL，详见 [版本控制与阶段交付](references/version-control-workflow.md)。策略明确后保存在当前上下文及续接记录，不重复询问。

## 使用示例

- “使用这个入口，修复背包刷新。” → 没有可沿用的选择时提供 A/B/C。
- “选 C，先反问帮我想清楚动画工具怎么做。” → 先查已有资料，每轮一个核心问题，不先追问 A/B，不改产品或构建；明确要求实施后沿用已有 A/B，未选则仅补选一次。
- “这次A级，修复偏移，不改变已有布局。” → 核对基线并在边界内连续推进。
- “这次B级，先讨论新工具的交互。” → 先理解、调查和提出重要取舍，不正式实施。
- “沿用当前等级，开始编写。” → 按已确认范围推进，不重新访谈。
- “只整理提示词，交给另一个执行者。” → 输出交接材料，不开始其中实现。

## 分发与限制

完整复制本技能目录，保留SKILL.md、VERSION、README、references和assets。领域/方法技能通过可见元数据按需组合，不是硬依赖；缺失时报告能力范围。

宿主适配、开发测试、索引和历史不属于本目录。仅拷贝文件不保证所有宿主自动发现；以实际配置与读取证据为准。没有工具能力不能承诺后台更新、自动压缩或并发安全。
