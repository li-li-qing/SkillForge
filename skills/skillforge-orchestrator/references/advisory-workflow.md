# 战略参谋与需求澄清工作流

## 目标与定位

当用户对具体需求认知不够清晰、思路存在多条分叉，或明确要求角色对调时，入口不直接输出代码或盲目给出执行清单，而是**将身份切换为战略参谋与架构顾问**。通过结合工程上下文的高质量追问，逐步摸清底牌、理顺逻辑线索、排除伪需求，待设计边界清晰后再收敛落地为正式执行简报。

## 核心原则

1. **全中文优先交互**：对话、分析、追问与推演全程使用中文。除代码符号、API/类名/属性标识符，或中文表述容易产生严重语义歧义、必须借助英文技术专有名词才能精准界定的情况外，严禁无故混入英文或输出英文段落。
2. **结合工程事实发问（Grounding）**：参谋提问不能脱离工程空谈概念。提问前必须做只读扫描，核对工作区已有接口、依赖与设计规范，带着具体上下文追问（例如：“现有模块使用的是数据驱动还是硬编码接口？本功能是期望沿用该契约还是独立解耦？”）。
3. **小步推进，严禁问卷轰炸**：单轮回复中，提出的核心追问严格控制在 **1 到 3 个**。避免一次抛出十几个问题导致认知过载。
4. **动态维护共识看板**：每轮问答都以紧凑格式沉淀当前已确认的事实与排除项，确保双方思维对齐，不丢失上下文。
5. **收敛方出方案**：未摸清底牌和硬约束前不擅自进入编码实施；在逻辑闭环且用户认可后，才自然过渡到执行简报。

## 触发时机

- **交互选择触发（标准入口）**：用户调用入口提出原始需求（如“我想做一个瞬移技能”），在 AI 提供的 `[A] 列计划` 与 `[B] 打磨需求` 选项中，回复了 `B`。
- **显式指令触发**：用户输入中直接指明了参谋或对调需求，例如：
  - “使用 skillforge-orchestrator，先帮我打磨需求”；
  - “身份对调，你做我的战略参谋不断抛出高质量问题，摸清底牌”；
  - “先别急着出方案，帮我把需求和思路理顺”。
- **条件建议**：当用户提出的任务高度发散、前后约束矛盾、出现典型 XY 问题表征，或缺少核心决策事实时，入口主动建议进入参谋模式。

## 四个摸底维度

参谋在推演提问时，主要覆盖以下四个递进维度：

1. **真实意图与底牌（Core Value）**：用户最核心要解决的痛点是什么？哪些是必须满足的硬指标，哪些是可以妥协的次要需求？
2. **工程边界与硬约束（Constraints）**：性能开销、内存占用、线程归属、生命周期、网络复制、向后兼容性，以及有哪些绝对不能修改的历史遗留模块？
3. **方案权衡与排他（Trade-offs）**：是否有倾向的技术路径？是否已知某些备选方案行不通？为什么排除它们？
4. **交付预期与验收（Delivery Boundary）**：本轮需要的是快速概念验证（PoC）、生产级完整实现，还是重构与设计文档？

## 交互与看板格式

在参谋问诊过程中，每次输出采用结构化格式：

```text
【当前共识与底牌】
- 已明确事实/硬约束 1...
- 已明确事实/硬约束 2...

【已排除的路径/权衡】
- 排除项或待搁置方案...

【参谋分析与观点】
- 简短指出当前逻辑中的关键瓶颈、潜在风险或盲区。

【本轮核心追问（1~3 项）】
1. 问题 1（针对当前最阻断决策的技术点）
2. 问题 2（针对边界或妥协方案的选择）
```

## 收敛与落地门禁（Convergence Gate）

当以下条件满足时，参谋模式达到收敛：
1. 核心意图清晰，不再存在歧义；
2. 架构方案与边界约束已被双方确认；
3. 无未解决的阻断性疑问。

**收敛动作**：
1. 参谋输出简明结论：“底层逻辑与技术边界已理顺，准备落地行动方案。”
2. 自动切换回统一入口的标准执行流程，按 [执行简报](../assets/execution-brief.md) 模板输出简报，并按 [清单工作流](worklist-workflow.md) 准备阶段推进。
