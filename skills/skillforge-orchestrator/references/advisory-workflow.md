# 战略参谋：带着依据提问，收敛后回到同一任务

## 触发与前提

用户选择 C、要求先反问理清需求/分析路线，或任务出现重要缺口时采用。明确选择 C 或先反问时，直接进入澄清，不先要求选择 A/B；记 `interaction_mode=clarify`，保留已有协作等级，未选则为 `unset`。澄清期间只读调查和讨论，不启动产品写入、构建或实施。B级不等于必须漫长访谈，A级也不能免除分析。首先完成入口的共同准备，读取个人习惯与适用领域规则；已有事实自行查，不问用户技术名词选择题。

没有工程时，依据已提供的目标和使用场景开展讨论，标明假设；不伪报读取源码，也不把无工作区当成无法思考的理由。

## 每轮只推进一个核心决定

从用户希望实现的功能出发，先说明已知事实与真正的不确定性。每轮给出若干有意义的选项，通常 2～4 个；逐项写清做法、优点、缺点和适用情况，再说明推荐及理由，最后请用户决定一个核心问题。选项数量随实际选择变化，不为凑数编造路线；已有唯一硬约束时说明依据，再讨论真正开放的选择。不要重复用户已回答的内容，不每轮倾倒整张看板。

围绕目标、使用规模、硬边界、长期成本与验收发现遗漏。已确认方案内的具体代码组织可自行决定，不请用户逐行审批；尚未明确的方案和功能细节仍按当前等级处理。非阻断改进及时提出，不能擅自追加。

用户不理解时用真实例子讲效果，避免“请选择技术A/B”而不解释用途。B级的方案、技术栈和未明确的功能细节须等待确认；未回复仅隔离相关决定。A级将重要未知留账并推进无关工作，不持续提问等人回来。

## 停止访谈的条件

目标、关键边界、可验证方向和第一轮验收足够明确，即可收敛；不要求所有未来细节全部确定。剩余未知按风险/依赖分类，重要高风险先局部验证，低风险可逆细节在允许范围内推进。

用户已明确要求开始实现：已有 A/B 则沿用，未选则仅补问执行阶段采用 A 还是 B；选择明确后转为 `interaction_mode=direct`，复核共同准备中有变化的证据、能力与技能路由，补短清单后继续，不重复问已知问题、不新增长提示词确认。用户只要方案：交付方案，不执行产品实现。“方案可以”或未回复不等于要求实施。

## 公开共识记录

保留目标、已确认约束、选项/采纳理由、暂定/待决、验收及信息来源。记录公开理由与证据，不存隐藏推理；技术经验和个人习惯按对应维护流程沉淀，不把这段会话全文复制进技能。
