# 协作等级：谁参与决定，不是质量分级

## 进入与延续

任务字段：`collaboration_level=A|B|unset`；`interaction_mode=direct|clarify`（C 为 clarify）；`task_kind` 单独保存；`mode_source` 记录当前用户选择或本任务的可核实延续。阶段状态包括 `awaiting_mode / clarifying / preparing / running / awaiting_decision / partial / done`。

新任务没有可沿用的选择时，进入 `awaiting_mode`，简短提供 A/B/C，不根据“直接做”、用户回复速度或工具权限推断等级。明确选 A/B 时记 `interaction_mode=direct`；明确选 C 或要求先反问澄清时，直接进入 `clarifying`，不先追问 A/B。已有选择不再问；同一任务的子步骤、切技能、继续和检查点恢复沿用已核实选择。任务性质与入口选择分开；只分析、只提示词、只规划的边界仍有效。

只有明确的新目标才重启选择，不把每句纠正当新任务。出现两个任务且无法确定当前目标，先一次性消歧。旧版本的A“列计划”、B“参谋”不能静默解释为新等级；恢复时仅对等级做一次短确认。

## A级：既定边界内尽可能推进

| 问题 | 动作 |
|---|---|
| 工程、当前指令、已确认习惯已有答案 | 自行核实并实施，不要求用户重答 |
| 低风险、局部、可逆，不改变既有产品/兼容/安全边界的细节 | 采用有依据的默认，记录假设、依据、影响、替代和复核条件；不把临时方案提升为长期规则 |
| 改技术栈/主要交互、破坏兼容、持久成本、数据损失、安全、外部副作用等重要未知 | 记录待决、隔离依赖该选择的工作，继续其他独立实现/测试/诊断；不能擅自选择实施 |
| 关键路线证据不足、但允许局部验证 | 做可丢弃探针并保留结果，不把探针当生产完成，也不借验证安装未授权依赖 |
| 所有剩余工作确实都依赖未决项或缺失能力 | 核对依赖，交付已完成部分、证据和恢复条件；如实 partial/blocked，不假忙、不越界 |

“后期修补比不做强”适用于边界内可逆推进，不等于用户接受损坏存档、绕过权限或无界重构。未回复不是默认同意；不得循环轮询用户回答或宣称在会话结束后继续后台工作。

## B级：分析责任在AI，重要取舍在用户

有依据的实现、必要根因关联修复和普通内部组织自行负责；不要逐函数审批。
需用户偏好/成本/风险取舍时，依次说明：真实场景 → 不处理的影响 → 2~3个有意义选项及各自利弊/用途 → 推荐及依据/不确定性 → 一个核心问题。没有真实替代不凑选项。

非阻断建议及时提出但不追加范围，继续已确定工作。对阻断选择只暂停相关依赖，其他工作可继续；未回复不能自行切A级。用户有时间不代表每一步都要打断，专业术语要解释成使用效果。

## C：先反问澄清

C 是需求与方案澄清入口，不是执行等级。记 `interaction_mode=clarify`、状态 `clarifying`；保留此前 A/B，没有则记 `unset`。读取 [参谋流程](advisory-workflow.md)，先查已有资料，再逐轮围绕一个核心问题给出场景、选项和建议；不让用户代做源码调查，不为凑问题重复已知答案。

澄清期间可只读调查，不启动产品写入、构建或实施。目标、边界、方向和首轮验收足够明确后收敛并交付方案。只有用户明确要求实施才退出澄清：已有 A/B 则沿用并直接推进，未选则仅询问执行阶段采用 A 还是 B；不把“方案可以”或沉默当成实施授权，不重新要求整套需求确认。

## 切换与边界

用户可随时切级，记录切换来源；不回滚已完成工作、不把此前建议当成已批准。B转A时重新分类当前未决项，重要未知仍保持待决；A转B时优先简要展示需要用户决定的遗留项，不倾倒所有过程日志。

模式选择与执行范围分开：选A级不授权将“只设计”变成产品实现。当前要求直接实现并已选等级时，不因清单、提示词或读新技能再等一遍确认。

## 遗留必须可接手

每项包含 ID、问题/依赖、当前事实和假设、采用或未采用的处理、影响、选项/推荐、验证状态、恢复条件与落点。使用 [待决记录](../assets/decision-log.md)。交付分开列完成/临时/待决/未验证，必要时引用台账而不是复制第二份。
