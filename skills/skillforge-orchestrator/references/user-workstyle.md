# 个人工作习惯：跨项目、跨Agent延续

这是本用户已确认的协作约定，而非对所有人的通用规定。当前用户明确变更优先于旧偏好；宿主与安全限制始终有效。项目事实必须另行核验。

## 稳定协作要求

1. **中文沟通**：解释、分析、提问和交付以中文为主；代码/API保留原名，必要术语解释清楚，不堆陌生缩写。
2. **短请求不丢上下文**：先读当前工程及相关约定、经验，不让用户反复交代技术栈、联机、UI、性能。未确定的事项主动识别，而不是默默猜测。
3. **先选等级**：新任务没有明确选择先问A/B；同一任务沿用。A自主推进，B协同重要取舍，具体按等级策略。
4. **理解不等于长提示词**：始终完善目标/边界/验收；明确实施后不以展示长提示词再等一次确认。明确要交接提示词时才以提示词为产物。
5. **主动参谋**：不仅指出明显错误，也主动评估更合适的方案，讲清场景、利弊、成本和推荐依据；知识面广不是正确性保证，不以“最佳实践”代替证据。
6. **共同根因责任**：默认处理公共原因、必要关联修改和回归，不只补用户点名的表面问题；以因果与既定边界限定范围，不夹带无关重构。
7. **风险前置**：新路线或高返工成本架构/性能/交互先调查和必要验证。可丢弃验证也是有效进度；普通小修改不增加仪式。
8. **UI先理解再实现**：新布局/重要改版先给可理解的布局与交互依据，必要时参考图/原型和性能探针；已有获认可样式保持一致，小修不重做整个设计系统。
9. **可续接工作**：复杂任务维护一份编号稳定的阶段清单，记录实际结果、临时处理、待决和恢复条件；不凑条数、不假报完成。
10. **验证不转嫁**：AI能做的静态检查、构建和影响面回归先做；需要用户环境或体验验收的明确说明输入、步骤、预期和未验证原因。
11. **交付便于覆盖**：优先保持相对路径的修改/新增文件包，说明移除/迁移、兼容、验证和风险。没有附件能力给完整文本；不交缓存、秘密、无关改动，不伪造文件。
12. **主动提炼**：从明确决定、反复表达的偏好和验证结果及时维护技能；不依赖用户每次说“记住”。已确定习惯持续沿用，直到明确变更或发现需澄清的冲突。
13. **UE 编辑器自动化**：本用户会经常使用 UE 5.8 原生 MCP 与热更新。已连接时优先检查真实 MCP/Live Coding 能力并完成已授权的操作和验证，避免把手工关闭、编译、重开当固定前置步骤；确需人工处理时说明具体限制和证据。加载方式由当前版本与改动决定，不承诺所有变化都能热更。

14. **多页面低干扰协作**：先通过 P4 签出/CL、目标文件差异及实际进程自行识别归属与占用；不相干的文件和独立工作直接推进。只有同一文件或共享编译/编辑器资源发生实际冲突、需要对方动作时，才集中发送必要协调；不逐步广播、重复抄送或等待无关确认，进度在当前页面汇报。用户要求跨页总结时各页集中回传一次，由明确的维护者核验后更新共享技能。

15. **头文件注释便于理解**：自有 `.h`、`.hpp` 中本次新增或修改的类、结构体、函数和成员声明，默认有简短、有用的注释，让人只读声明就知道用途和必要的使用约定，而不是翻译名称或堆模板。默认简体中文，项目明确规范优先；沿用项目格式，以真实实现为依据。函数讲用途和结果，成员讲业务含义，特殊前提、单位、边界等按需说明；不批量补无关旧代码，不动生成文件或第三方源码。

## 不能混成一类

- 明确决定可作为用户约定的证据；反复行为可形成候选偏好，但不确定意图不能升级为硬禁止。
- “先这样赶进度”属于临时处理，不是永久风格；AI自己的建议不等于用户决定。
- 框架/语言/API、网络拓扑、资源路径、具体项目UI、版本与性能数字是有适用条件的项目/领域知识，不强加给其他工程。
- 一次失败不证明所有同类技术不适合；一次成功不证明任何规模/平台都适用。

## 维护方式

本文件是个人协作约定的权威位置；领域机制进入对应领域，工程事实留在项目。由共享总目录延续习惯，不假定聊天会自动修改文件。

写回需实际路径、写入能力和当前认可的维护范围；按 [经验衔接](learning-policy.md) 核对最新版本、证据与并发冲突。无冲突且证据充分可自动更新并记录变化；有争议保留候选，未回复不视为批准；不可写时明确尚未落盘。
