# 先列清单，再按阶段推进

这是用户认可的跨项目工作偏好。用途是让工作可检查、可续接，避免漏项和重复实现；不是要求所有任务都生成长文档。先遵守当前请求、项目约定和宿主权限。

## 选择清单形态

| 当前任务 | 采用方式 |
|---|---|
| 单点、低风险、可在本轮完成的小修改 | 在回复中列几条动作/验收，随后完成，不额外创建长期台账 |
| 跨模块、有多项依赖、跨批次或用户要求长期推进 | 维护一份 Markdown 阶段清单；优先复用用户指定或已有的文件 |
| 用户只要计划、待做列表或执行提示词 | 交付所要求的清单/提示词，不开始实现；明确要求文件时可写该文件 |
| 用户已批准实施或正在继续已授权范围 | 先补清单，再持续实施与回填；不因列清单或换批次再次索要相同授权 |

没有文件写入能力时，在回复给出完整可复制清单并注明未落盘。未指定位置时按当前项目文档约定选择一个本地位置，不默认安装到宿主技能目录或加入版本控制。纯问答不强制套实施清单。

## 1. 核对实际起点

读取相关项目指令、当前源码/资产消费点和现行设计，再检查未提交工作。区分已有实现、待补缺口、仅需接入/验证和未定规则；计划不能只凭名称或截图猜机制。

通用机制优先放入该项目已有的可复用层，具体内容、数值、素材和表现留在消费工程；仅在项目确有插件分层时使用“插件/项目”归属，不要求普通工程为清单创建插件。已有基础优先复用，不为了任务数量再造系统。

记录目标、范围、非目标、真实约束与证据入口。规则不确定时先列设计任务，下游实现依赖该决定；不能把猜测写成已确定功能。

## 2. 按可验收阶段拆解

采用 **阶段 → 大模块 → 子模块 → 独立任务**；简单任务可以省略没有意义的层级。大模块是工作分类，不等于新建代码模块。

每阶段写进入条件、通用层产出、项目消费、定向验证与完成标准。先形成最小可验证闭环，再扩展覆盖；保存、多人同步、取消与资源清理随所属功能推进，最后只补跨模块组合验证。

每项必须说明：稳定编号、状态、归属、类型、优先级/交付阶段、依赖、真实落点、具体动作、产出、可观察验收、证据与阻塞。使用 [模板](../assets/worklist.md)，按任务补充字段，不机械复制空表。

- 多数任务以约 1～4 小时独立工作单元为参考，开工复估；超过一个工作日且可独立验收的职责继续拆。条数不能换算人日。
- 动作写清在哪个入口改变哪个行为、产出什么；不得仅重复标题，或给不同任务套相同泛化动作/验收。尚不存在的接口明确标“拟新增”。
- 验收写输入/触发条件、预期状态及检查方法。例如“取消后恢复正常”应拆成停止能力、归还碰撞/运动/锁、结束音画、释放占用，再检查顺序与幂等。
- “1～1000”若只是编号示意，则不设配额或上限。覆盖未完整就继续编号；不为整数凑数，也不为限制总数合并独立职责。用户明确要求固定数量时按当前要求执行。

## 3. 审查覆盖与重叠

针对各项考虑正常、失败、取消、重复、并发、生命周期、网络、保存、资产和作者/调用者使用路径。只检查该任务适用的维度；纯文档没有运行时会话时说明不适用，不能凭空扩展产品范围。

复杂清单增加覆盖矩阵：能力 → 实现/复用入口 → 项目消费 → 异常处理 → 验收编号。共用机制和验证通过编号复用；证据版本、入口、配置或拓扑不同，须补实际消费验证。网络/保存不适用的工程不强加这些系统。

审查语义重叠，不只比较标题。旧任务“接入声音和特效”拆为两个细项后，旧项不能仍作为第三份交付。全部范围内能力都有明确路径、必要异常和验收，才算清单覆盖充分；编制完成不等于这些能力已实现。

## 4. 保持编号与依赖稳定

- 编号是身份，执行顺序由依赖和阶段索引管理。续写沿当前最大编号追加，不因换阶段重排，不复用已取消编号。
- 保留已发布内容的状态和证据。拆分未完成任务时，原项记“取消/已拆分”及子项编号，子项记来源；将有效后继改为依赖所需子项或完整覆盖它们的汇总项。
- 已完成任务的后续扩展另加编号，不倒改其完成证据。删除或取消任务留原因；不要把取消计作完成。
- 校验编号唯一、新号连续、依赖存在且无环、有效项不依赖取消项、阶段前置合理、引用存在、字段齐全。阶段倒置时重排阶段或修正过宽依赖，不能静默忽略。

例：原清单止于 WK-0030，WK-0012 同时承担回滚与释放锁。新增 WK-0031、WK-0032；WK-0012 保留并注明替代，原后继按需要依赖两个子项；其他已发布编号不动。

## 5. 执行、回填与继续

每批通常选择 3～8 项依赖已满足的任务，优先完成一个小闭环；可在批内先完成前置再做后继。数量是组织参考，不让本轮已授权工作因做够一批便无故停止。

开始前重核源码、文件范围、未提交改动与规则决定。结束逐项回填实际产出、验证和阻塞；未满足验收保持待做/进行中/阻塞。外包或规则阻塞时说明恢复条件，继续其他独立任务。只维护一份当前状态台账，简报和 Checkpoint 引用它。

实现、编译、自动化、资产检查、真实运行及人工验收分别记录；未执行不能写通过。验证只做与改动及风险有关的必要检查，不因条目多而机械增加镜像测试。

交付清单位置、修订摘要、编号总数/有效数/取消数、实际证据、未完成项和下一批入口。不自动创建目标、不自动提交/发布，不把维护清单理解为获得这些额外权限。使用目标模式时，仅在用户已授权的目标范围持续推进。
