# WorkBuddy：技能读取与执行效果检查

核对日期：2026-11-14。用户报告在 WorkBuddy 中使用 DeepSeek/GLM 时效果不如当前会话；尚缺具体模型标识、版本、失败回答和工具轨迹。本页列检查方法，不宣称已定位根因或测得改善。

## 先固定比较条件

在新任务中记录客户端版本、模型选择器的准确名称、实际工作目录、技能来源/版本和启用状态。再记录可见的思考强度、上下文窗口和经济模式；不可见就写未知，不由品牌猜测能力。

官方技能文档说明：关闭技能不会从已加载的当前会话移除它，新任务才完全生效；并建议只启用当前任务所需技能。因此比较旧/新版规则时都新建测试任务，用同一请求和最少必要技能，避免旧会话残留。正常产品工作不必为每项任务重开会话。

官方模型文档说明经济模式会自动压缩上下文。记录是否观察到压缩；不要从“忘记要求”直接断定压缩错误，也不默认关闭经济模式或调到最大档位。需要定位差异时，每次只改变一个条件，并比较实际质量与成本。

## 一个只读加载检查

在允许读取当前项目和已安装技能的测试任务中发送：

> 使用 skillforge-orchestrator，B 级，只做只读检查。列出你实际读取到的入口路径/版本，以及本题必需但读不到的参考文件；不要根据技能名称猜内容。随后解释：如果我只要大型改动的 spec 和 todo，这次会推进到哪里？没有真实读取能力时直接说明，并依据已提供正文回答。不要修改产品或配置。

不要只看模型自称“已使用技能”。有工具轨迹时核对真正的读取路径/内容；没有轨迹就保留未知。检查导入的是完整技能目录，`references/`、`assets/` 和入口来自同一版本；只上传 SKILL.md 不能证明引用资源可达。仓库副本更新不等于 WorkBuddy 已安装副本同步。

## 根据断点处理

| 实际现象 | 优先检查 | 后续动作 |
|---|---|---|
| 找不到入口或读到旧内容 | 是否安装/启用，当前任务是否残留旧加载，实际技能来源和版本 | 用新测试任务核对完整包；没有证据不归因于模型。 |
| 入口已读，参考文件未读/不可达 | 目录是否完整、当前阶段需要哪些资料、宿主读取权限、工具输出是否截断 | 只补当前必要资料；能力限制留明，不能假称已加载。 |
| 全部必要材料已读，仍跳步骤/漏约束 | 当前任务、允许范围、当前阶段、完成条件是否明确，其他规则是否冲突 | 用同一案例比较旧/新指令；以实际动作和产物评分，不靠复述规则。 |
| 工具失败或循环 | 实际调用参数、错误、工具结果回传和接入方式 | 保留最短失败轨迹再定位；文字技能不能修复连接器错误。 |
| 流程遵守但代码结果不正确 | 工程事实、接口/版本依据、目标环境及验证覆盖 | 按领域排障处理，不能把技术能力问题一律当作技能太长。 |

只启用入口与当前任务真正需要的领域/方法技能是排查条件，不要求卸载其他技能，也不把停用当作已从当前上下文移除。

## 最小行为对照

选同一个真实失败任务，分别使用旧/新版技能，保持模型、任务材料、工具权限与可见设置一致，各用新测试任务。先检查读取证据，再看目标行为：是否保留硬约束、在正确范围行动、补了必要事实、真实调用工具、交付可验证结果。长回答或重复“遵守规则”不计为完成。

保存原始请求、回答、可取得的读取/工具轨迹、实际产物、时间/调用成本与限制。没有目标模型环境时只保留题目和执行步骤，标 not_run。一次对照只能说明该样本，不证明其他模型或长任务稳定性。

## 官方依据

- [WorkBuddy 技能](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)：启用/关闭的会话边界、完整导入及只启用必要技能的建议。
- [WorkBuddy 模型配置](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)：模型选择、思考/上下文设置与经济模式。

这些说明核实宿主行为，不证明用户本机配置或某个模型的表现。主技能保持同一套规则，不把此处品牌和设置复制进运行核心。
