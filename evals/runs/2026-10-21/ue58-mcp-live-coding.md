# UE 5.8 MCP / Live Coding 技能补全

用户要求：将经常使用的 UE 5.8 原生 MCP、热更新和验证流程补入 SkillForge，并更新本机已安装的 Skills。

## 范围与依据

- 修改现有 C++、蓝图与个人协作约定三个 Skill；技术细节分别放入两个自包含参考，不新增泛用 Skill，不引入固定项目路径或 MCP 命名空间。
- Epic UE 5.8 Unreal MCP 文档与 Live Coding 文档；本地对应引擎的 ModelContextProtocol.uplugin、LiveCodingModule.cpp、LiveCodingSettings.h、UObjectGlobals.h。
- 本次现场曾在缺少直接 Compile 工具时过早要求手动关闭 Editor；随后经 MCP 官方 Slate 控制台发起 LiveCoding.Compile，UBT 成功并完成重载，新 M_Test PIE 的原生虚函数查询得到正确倒挂眼位。这组末尾修正没有增加反射布局，不能据此声称任意反射变化都已实测。

## 修正

1. 先发现工具集和 schema，确认工程、进程、世界及运行实例；三个发现元工具不是能力上限。
2. 区分已有函数/虚函数覆盖、受支持的对象重实例化、新增 MCP Tool 声明、构建/装载配置变化；按证据选择热编译或常规构建/重开。
3. 记录构建、重载、运行反射、蓝图调用方、新实例行为与普通目标构建的分别状态；Type/Click 成功不是编译完成。
4. 保留用户已有 PIE、未保存地图和他页归属，串行使用共用 Editor/UBT。需要人工步骤时解释具体限制。

## 验证记录

- 更新前独立文档基线评测：两例，评测者已能选择普通原生变化的 Live Coding 路径，并拒绝把 Compile=true 当完成；指出旧“正常构建”措辞缺少支持重实例化时的清晰分支。该基线未复现一律关闭行为，不声称存在独立 RED。
- 候选独立文档评测：三例，分别覆盖普通原生 override、无终态/反射仍旧、以及新增 MCP Tool UFUNCTION。回答均区分了入口成功、重载与验证；评测指出“验证失败就重启”范围过宽，已收窄为确认的加载/重实例化限制或构建重载后反射仍旧，编译错误先修源码、功能失败先诊断。
- 追加 CPP-116～CPP-118、BP-06～BP-07 五个行为规格；不是五次独立 Agent 实测，也不是本轮额外运行了 UE 测试。
- 候选三包结构、引用和独立拷贝校验通过，skill-creator quick_validate 三包通过。
- 现有补丁安装器测试 13 项中 12 项通过；test_target_symlink_rejected 在 Windows 建立夹具符号链接时因 WinError1314 权限不足报错，尚未进入该项断言。保留此环境限制，不改测试、不申请管理员权限，不记整组全绿。
- 正式写入使用已有 apply_skillforge_update 的前后 SHA 核对、协作独占锁、备份和逐文件原子替换。只同步本次七个运行时文档到已安装目录；发布前检查与写入后复验结果记录在本次本地事务中。非协作程序仍可绕过该锁，不宣称多文件原子事务。

源目录修改、已安装文件同步与编辑器运行验收是三件事。本轮技能维护不再修改项目资产、启动 UE 验证或提交 P4/Git；官方文档的反射支持说明与本次末尾原生修正的现场证据分别保留。
