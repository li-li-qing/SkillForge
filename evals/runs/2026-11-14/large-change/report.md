## 实际改动

保持 14 个技能，入口版本 0.4.0。六步流程和 spec 模板放在原入口包内，复用澄清、清单、续接和协作规则；todo 对应需求/验收编号，按项实现/验证/回填，处理变更、依赖阻塞与恢复。小任务仍可用短清单。

共同准备按当前缺口选择资料，不把能力、路由、上下文和长期清单都作为每项任务完整展开的步骤。专业技能内容未改。首轮整合时入口正文 UTF-8/LF 字节从 8052 变为 7645；后续优化见末节。这只是文本大小变化，不等于上下文 token 或质量收益测量。

README 展示当前用法，原经验/验收/历史导航原文移动到根 CHANGELOG，逐段核对保留；旧证据没有删除。宿主专项排查放在 `adapters/workbuddy/README.md`，核心无品牌分支，没有自动安装、修改宿主设置、提交或推送。

## 两轮配对冒烟

执行材料与限制见 protocol.md。旧版和新版分别使用新上下文子代理，第二轮不再读取技能，沿用各自第一轮已读规则。两边题面、规划范围和读取权限相同；评分规则没有交给回答者。允许回答后把冻结正文写入限定的评测文件，产品项目仍不可写。

原始输出：baseline-turn1.md、baseline-turn2.md、candidate-turn1.md、candidate-turn2.md。只记录当前会话可调度子代理的表现；具体服务端后端 ID 和目标模型版本未取得，不猜型号。保存了执行者自报路径，但没有导出完整独立工具审计，因此不声称完整隔离盲评或完整端到端实测。

旧版已正确沿用 B 级和只规划范围、保留 CSV/JSON 与旧映射约束、区分取消决定和工程未知，也已经能形成 spec/todo 与部分验收对应。新版没有从“不会规划”变成“会规划”，不能据此编造失败基线或称为正式行为 RED→GREEN。

新版第一轮先聚焦取消选择，开发细项留待工程与规则收敛，只列5项决定/调查/规格任务；旧版第一轮已展开13项、包含未来开发与组合验证。第二轮两边均保留“取消回滚本次新增、保留历史记录”的决定并注明未实现、未运行。新版保持原有5项编号，把决定记录与实现验证分开。

正文字符数（含附注）为：旧版第一轮6408、第二轮4985；新版第一轮3660、第二轮3871。长度缩短是这个样本的观察，不是质量评分、token 成本或稳定改善证明。

新版具体实现和运行验证被延后到 WK-0005 的进一步拆解，尚无完整开发任务的逐项覆盖证据。因此本次样本只支持“规划边界和关键决定保持、前期展开较少”，不支持“全部需求/异常已有完整开发与验证任务映射”。阶段6的真实代码开发、失败修复、跨会话接管尚未运行。

## 跨模型问题

用户确认使用 WorkBuddy，尚缺客户端版本、准确模型名称、失败请求/回答及读取/工具轨迹。官方说明支持核对技能开关的会话边界、最少必要技能、模型/思考/上下文配置和经济模式；专项文档保留官方来源与检查步骤。

内容分散、步骤选择和加载链路是可检查的因素，不是已证实的用户故障根因。尚无 WorkBuddy、DeepSeek 或 GLM 的实际测试；不能因本环境结构通过或一次文本样本就声称目标平台效果变好。现行 LC03～LC08 未运行；LC01/LC02 只有上述两轮冒烟，题库状态不批量改成通过。
