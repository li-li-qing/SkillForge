**1. 单一源 Socket 的变换与两个表示**

源 Socket 的世界 Transform 属于动画源 Mesh 所在的世界空间。可见角色经过 Runtime Retarget，并可能受独立组件偏移、网络平滑和外观手部补偿影响，因此“源骨架上的世界位置”不必就是“显示角色应呈现的位置”。直接赋值可能把源 Mesh 与可见 Mesh 之间的组件差异带到剑上。

先核对实际组件合同：Socket 是骨骼局部、源 Mesh 组件空间还是世界空间；武器 Offset 定义在哪一层；最终附着组件又是哪一个。如果视觉武器应沿用源 Socket 在 Mesh 内的姿态，再放到可见 Mesh 的组件基准中，应先把源 Socket 世界变换转换为源 Mesh 组件空间，再通过约定的显示组件变换映射回世界空间，按实际 Offset 顺序组合。不能在没有读实现时断言这里必然只需一条固定乘法公式，尤其要检查非统一缩放和重复转换。

两个表示必须分开核对：

- **视觉武器表示**服务握持与画面，其定位须符合显示和平滑合同。单一源 Socket 提供统一校准，外观通过重定向和局部手部补偿贴合，不给每个 Avatar 重新标定全部武器。
- **服务器 Trace 表示**服务命中检测，核对实际 Mesh、`trace_start/trace_end`、攻击窗口及服务器更新时序。不能因为视觉剑贴手，就认定权威 Trace 正确；也不能把客户端显示位置直接作为命中真值。

参考说明了单一源 Socket 和两个表示的职责，但没有给出本项目的最终变换实现，因此上述映射必须由实际组件合同确认。

**2. 曲线为 1 仍不更新与 PreUpdate 验证**

先确认这个“1”来自本帧实际求值姿势、目标 AnimInstance 和目标节点输入，而不是原始资产、Chooser 输出、其他实例或上一帧缓存。再检查最终层权重、曲线经过的混合节点、节点是否被相关性剔除，以及隐藏源 Mesh 的 Tick、LOD 和更新条件。

对自定义 AnimNode，我会依次验证：

1. 实际运行的 AnimInstance 使用的是重新编译后的 AnimBP 生成类，图中节点确实是该自定义节点，运行对象不是旧实例。
2. 查当前引擎中节点声明预更新需求的接口，以及 AnimBP 编译器收集预更新节点的路径，确认自定义节点满足收集条件。
3. 编译后检查生成类或其动画类接口中用于调度预更新的节点记录，确认其中包含目标节点。
4. 在调度入口和节点 `PreUpdate` 中设置断点或带对象路径、世界、帧号的诊断，确认实际调用及更新后的快照被同一实例动画线程消费。

“实现了 `PreUpdate`”和“编译成功”都不能证明它已经进入生成类的预更新调度。本次参考没有描述这些接口和容器的精确名字，也未读取引擎源码，因此不声称已验证 UE 5.7 的具体收集实现。

覆盖曲线应按明确合同处理：

- 无效值，例如 NaN/Inf，不能直接传播到混合权重；使用约定的安全默认值并提供诊断。
- 缺失曲线必须与合法的零值区分，并约定回退。若曲线语义是“全身动画已覆盖持剑姿势的比例”，一般零覆盖意味着保留持剑层；不能把缺失直接视为完全覆盖。
- 部分覆盖按连续权重混合；在上述语义下，可使用基础持剑权重乘以 `1 - Clamp(Coverage, 0, 1)`。实际多个风格、曲线合并及骨骼遮罩仍需服从项目合同。
- 切风格、重建实例及混合期间应避免旧值残留。装备 Tag 不能替代当前姿势的覆盖证据。

不能直接用“双遍求值”作为修复。需先证明当前图结构是否能先取得相关输入姿势及曲线、再在一次正常求值中决定持剑混合。重复更新或求值可能重复推进状态或引入额外成本；参考没有提供双遍方案或安全性证明，当前无法承诺可用。

**3. 新武器接入顺序与交付门禁**

1. 建立状态 × 步态 × 方向 × 风格覆盖表，逐一列出 Walk、Run、Idle、Start、Stop、Pivot、空中及缺失过渡。把“拥有素材”“已接入”“运行时实际播放”分开记录。
2. 核对第三方源 Mesh/Skeleton、离线目标、运行时动画源及显示 Mesh。先验证重定向姿势、手脚、骨盆、根轨迹与身体周期，再处理项目派生动画。
3. 校验循环、播放速度、Root、曲线、Notify、完整时间轴和采样范围。覆盖曲线按实际动作是否覆盖持剑姿势制作，不能仅按武器 Tag 批量写满。
4. 复用相容 PSS，建立或补充 PSD；根据真实 Chooser → Sequence/PSD → BranchIn → MM/Blend Stack 链接入。缺失过渡使用明确且可达的现有回退，保留空手、其他武器及空中行为；不能为了“全部接入”伪造不存在的素材。
5. 验证实际动画选择、播放时间推进及起停/转向切换，再验收可见握持、源/显示空间、远端表现与权威 Trace。
6. 攻击先交付完整的零伤害预览。逐击审核后，才制作正式 Montage/Section、命中窗口、续招窗口和服务器伤害配置。

可交付门禁是：

- **资产接入完成：** 骨架与派生数据检查通过，索引有效，引用及回退明确。
- **移动表现完成：** 目标状态实际选中并播放，过渡、循环、方向和握持经过视觉验收；缺素材限制明确记录。
- **攻击预览完成：** 完整动画能预览，保持零伤害。
- **五段正式攻击完成：** 五击的时间边界、命中和续招窗口经过逐击审核，服务器验证、命中/击空/去重、取消及真实联网通过。
