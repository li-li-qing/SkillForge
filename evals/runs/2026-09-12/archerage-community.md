## 冻结原始答案

### AR-06

先沿事件入口、订阅注册/停用、分发结束提交，及定时器执行、取消、再次入队分别画状态变化。B 很可能先进入待添加队列，停用只处理活动表，最后待添加仍被提交；这是待核对假设，不能直接认定。契约应是同一分发周期内最后有效操作决定订阅状态：取消必须覆盖待添加，分发快照不能让已取消项继续执行；明确新订阅从下一轮生效。重复定时器在调用前后都检查活动状态与 generation，回调中取消后不能被无条件重排。不要靠节流掩盖错误。

行控件的对象身份不等于当前物品身份。绑定乙时更新绑定版本，查询捕获物品稳定标识、行绑定版本和 owner/generation，回包同时核对，过期结果丢弃；回收时解除订阅和任务。诊断只记录必要的订阅 ID、待处理操作、计时器状态及绑定身份，限量且可关闭。没有工程时这些是设计契约，具体容器与取消接口待查。

最小回归用伪事件和可控时间覆盖 A 添加后取消 B、取消活动 B、重复初始化、计时器自取消，以及甲查询晚于乙绑定返回；断言下一轮 B 不执行、取消后无排期、乙不显示甲。补测正常注册、正常重复计时及当前查询成功。Ace3 的宿主依赖和许可均未核对，不复制到 toc.g；只借鉴机制并落到现有边界，本地模拟仍须客户端验证。

### AR-07

pcall=true 只代表调用未抛错，事件到达也不代表属于甲。先列出查询发起、当前搜索条件变化、事件参数、结果读取与 UI 应用各边界；核对现有接口是否带请求标识、物品稳定 ID、查询条件或结果版本，不能发明字段。请求记录至少保存目标与条件、owner/generation、请求序号、截止时间。回包只有关联证据一致才应用；若接口无关联能力，序列化插件请求也无法阻止玩家搜索，需检测搜索上下文改变并废弃请求，无法确认时显示未知并允许重新查询。

关闭或重开窗口使旧 generation 失效，迟到结果不能写新实例。最新报价作为带来源、时点和条件的当前快照；历史交易保留成交时事实，不批量覆盖，利润按所用报价时点明确展示。

团队整理每一步保留移动前状态、预期目标状态和操作身份。TEAM_MEMBERS_CHANGED 仅触发重新读取实际队伍，确认目标成员确实到达预期位置后才推进；无关成员变化不算完成。超时进入未确认状态，先读取现状并核对权限、目标有效性及可重试条件，不能盲目重复副作用调用；取消、窗口重开或手动改队应使旧计划失效。

回归覆盖甲查询被乙搜索打断、乱序和重复事件、无关联结果、窗口重开迟到结果；团队覆盖无关事件、实际成功但事件延迟、失败与超时、人工插入变更。这里只准备断言与观测点，未证明 RU 接口及游戏效果。

### AR-08

目前没有原始日志，不能判断少了多少或指定 RU 参数下标。先确认统计口径：逐击列表的展示筛选不应直接决定总 DPS/HPS，持续伤害被过滤会漏计；DPS 的时间分母、战斗起止也需独立核对。按显示姓名归并会把同名来源混合，并让改名后的同一来源割裂，应优先使用当前契约确认的稳定单位标识；无法确认归属时进入未知来源，不猜身份。

建立原始事件到规范记录再到聚合的单一接入链。保留事件名、来源和有限原始参数样本，核对正常直伤、持续伤害、治疗、吸收和空值各类含义后再映射。解析失败标记未知与原因，不写成合法 0；从尾部找正数可能把其他数值当吸收量，应移除猜测规则，契约未明时不计入吸收总量并报告覆盖限制。治疗总量与有效治疗、过量治疗若数据不足要明确区分，不能臆造有效 HPS。

多个订阅可能报告同一击，也可能是数值相似的真实多击。核对是否有稳定事件身份；无身份时先确认各来源覆盖并选择主来源，不凭相似值强行去重，也不无条件相加。总计只接规范记录，显示筛选在其后独立进行。

回归准备带已知期望的样本：直伤加 tick、同名不同来源、合法零与不可解析量、尾部多个正数、同一事件重复投递和真实连续同额多击，并核对时间窗口。没有原始样本只能验证自建模型；下一步需要最小匿名原始事件与环境版本，不能宣称计量已准确。

## 更新后条件：冻结原始回答

### AR-06

目标是取消后不复活、旧结果不写新绑定。现有信息只支持三个待验证假设：取消遗漏待加入队列、回调后无有效性检查、复用只验证控件存在。取证记录 owner、订阅/任务身份、generation、分发深度、活动与待加入状态及排期点，不靠 UI 节流遮蔽。

分发契约可定为新增到最外层退出才合并，下次分发生效，嵌套分发不可提前合并；取消同时使活动项及待加入项失效。使用稳定快照或延迟变更，不能遍历中任意新增键；快照调用前检查取消。异常也必须恢复深度并清理队列；重复注册与取消按具体订阅身份处理，不能误删其他 owner。定时器入口与用户回调返回后、重排期前各检查取消及代次，取消令旧闭包可见失效；保留含 nil 参数数量，约定长帧预算。行绑定存实体身份、绑定代次、请求身份，迟到结果三者匹配才应用；释放清事件、任务、数据和交互状态，重绑完整初始化。

最小回归以调用序列为断言：正常、新增、A 注册取消 B、取消自己/他人、嵌套、抛错后下一事件；定时器执行前/内部取消、owner 停用、旧代迟到、重复取消；甲查询→释放→乙复用→甲返回不写→乙返回能写。连续重载核对一次事件一次调用。Ace3 仅借机制，其 WoW API 与许可证不能当 RU 兼容证明；不整包塞 toc.g。以上是分析及待执行回归，没有工程修复或客户端实测。

### AR-07

甲利润被乙报价污染，首先核查共享事件到缓存的归因边界。提交保存物品身份、实际可得的品质、计价单位/数量、时间及窗口和请求代次；有真实请求 ID 才使用，无 ID 则用响应确实含有的字段和只读核实。代次只能阻止旧状态写入，不能证明无身份事件属于甲；无法关联保留未知，允许串行也不能消除玩家搜索的干扰。关闭窗口使旧代失效，结果入缓存前及写界面前核对关联和当前绑定。

pcall=true 只证明未抛错，仍需核查逻辑返回、结构和实际状态；空、零、未知、失败分别处理。市场估价缓存、交易锁定快照、真实到账证据分开，刷新报价不回写已确认历史收益；成本缺失标未知或估算，预计到账时间不当实收确认。

团队操作采用输入快照规划→检查权限/战斗/成员及能力限制→提交→等待→重读成员实际位置确认的流程。TEAM_MEMBERS_CHANGED 只是重查信号，无关或重复事件不推进。超时先查目标是否已达成；未知则暂停核实，未生效也须重新检查条件后按有界策略处理，禁止盲目重发；每一步前重核成员集合，变化使旧计划停止或重规划。规划不修改调用方成员表，避免浅复制污染预览。

回归覆盖手动乙搜索、旧窗迟到、重复/无关事件、同品异品质和单位、缓存过期及未知报价、历史快照和未到账；团队覆盖超时已生效/未生效、成员或权限变化、取消和重复规划输入不变。可准备纯逻辑与适配层模拟，当前均未运行；RU 方法名、返回与实战确认待客户端证据。

### AR-08

不能据“偏低”判断具体漏了多少：持续 tick 过滤会漏算，重复入口又可能多算，需先拆开各阶段。先定义整场或个人活跃时间、战斗起止、分母零值，以及 DOT/HOT、宠物、自疗、有效/过量治疗、吸收、免疫及晚到事件口径。逐击展示的过滤选择不能直接用于总 DPS/HPS；显示刷新与采集独立，隐藏窗口不停止应持续的统计。

接入前准备按事件类别和客户端版本采样：来源、实参数量、每个位置类型和值、参与对象与已知操作，显式保留中间/末尾 nil，不用 ipairs 或表长度证明完整性。不猜 RU 金额或吸收位置；逐类核对后转换为内部记录：来源/目标身份、类别、技能、时间、金额、解析状态和证据。未知金额保留原因，不能归零；尾参首个正数可能是别的字段，吸收无契约先标未覆盖。姓名只显示，使用实际可得稳定身份；没有则声明身份范围和同名歧义，不能发明 ID。

列出原始事件、共享包装服务和日志各入口，优先选择权威单入口消除重复接入。有可靠事件 ID/序列才按契约去重；同名同额近时不是证据，会误删连击和持续跳数。给每条输入保留已计入、口径过滤、解析未知、已证重复或待核状态，分伤害/治疗对账数量及金额。

准备人工确定期望的最小序列：普通命中、持续跳数、宠物/自疗、同额连续命中、重复入口、未知字段、含 nil、晚到事件与零分母；逐段比较解析→分类→累计→显示及总量/持续时间。当前没有原始样本，无法确认参数或漏事件量，只有诊断和接入方案，未运行 Lua、未游戏实测。
