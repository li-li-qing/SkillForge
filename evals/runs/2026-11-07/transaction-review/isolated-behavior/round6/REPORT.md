## 客户端属性 + 无参 Server RPC
两者均明确：
1. 普通复制属性服务器→客户端，客户端赋值只改本地副本。
2. Reliable RPC 不捎带客户端属性；不能靠延迟、ForceNetUpdate 或 Multicast 修复缺失的上行数据。
3. 在同一次 Server RPC 传槽位意图，服务器按拥有权、范围、库存和业务状态校验后权威使用。
4. 本地预测/UI 与权威结果分离；拒绝且属性未变化时不能只依赖 OnRep。测试含 dedicated server、拥有者、其他客户端、非法/陈旧请求及 listen host。
5. 合成逻辑审查和测试预期与真实运行明确分开。

候选答复额外给当前 Epic 属性复制/RPC 文档链接并声明页面显示 5.8 不等于工程版本；旧答复也正确，并未因较少官方页面核对而产生本题错误。

## GAS 两装备聚合栈卸载
两者均明确：
1. AggregateByTarget 下 handle 标识聚合 active effect，不是装备独占租约，A/B 可能共用实例。
2. 默认移除通常走 -1 全栈语义；所查文档的默认参数展示不足，落地须核对项目版本头文件/封装，不把网页签名当完整源码契约。
3. 本题同质、Infinite、每件确实贡献一层，可显式移除一层并维护来源贡献/授予代次账；不能把 apply 返回 handle 当作新增一层保证。
4. 减一层只减少共享总数，不代表 GAS 精确识别“A 那一层”；独立来源需求可采用非堆叠实例。AggregateBySource 不自动等于按装备隔离，同 source ASC 仍可能聚合。
5. 覆盖卸 A 保 B、卸 B、保 B 重装 A、重复卸装、外部清除、陈旧 handle/代次和失败路径；未运行明确标注。
