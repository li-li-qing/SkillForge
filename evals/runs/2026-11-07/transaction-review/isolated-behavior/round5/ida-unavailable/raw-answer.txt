- 实际工具：file 5.46、GNU readelf/objdump 2.44，以及 nm、strings、sha256sum。完整静态命令和原始输出见同目录 trace.txt。

## 函数说明
1. take_damage，0x1139，31 字节，范围 [0x1139, 0x1158)。名称来自符号表；DWARF 给出参数 amount 为 4 字节有符号 int，函数无返回值类型。0x1140 比较 amount 与 0，0x1144 的 jle 在 amount <= 0 时跳过修改；否则 0x1146 读取 health，0x114c 做 32 位减法，0x114f 写回 health。没有最低为 0 的钳制，也不修改 score。直接调用点为 main 的 0x1161。
2. main，0x1158，55 字节，范围 [0x1158, 0x118f)。0x115c 将 7 放入 edi，0x1161 调用 take_damage；0x1166 读取 score，0x116c 读取 health；0x1183 调用 printf@plt（0x1030），格式字符串位于 0x2004，为 "%d %d\n"；0x1188 设置返回值 0。
3. 启动和收尾代码：_start（0x1050）把 main 地址交给 __libc_start_main；_init（0x1000）条件调用 __gmon_start__；frame_dummy（0x1130）跳转 register_tm_clones（0x10b0）；deregister_tm_clones（0x1080）及 __do_global_dtors_aux（0x10f0）承担运行库清理，后者包含防重复标志和 __cxa_finalize 调用；_fini（0x1190）只有栈调整及返回。这些不属于训练样本的扣血业务函数。

## 全局数据与人工伪代码
health 位于 ELF 地址 0x4018、文件偏移 0x3018；score 位于 0x401c、文件偏移 0x301c。两者均为 4 字节，原始字节均为 64 00 00 00，即十进制 100。DWARF 将二者标为 volatile int，并与指令访问宽度相符。

```c
// 基于符号、DWARF 和汇编整理的 C 风格伪代码
volatile int health = 100;
volatile int score = 100;

void take_damage(int amount) {
    if (amount > 0) {
        health = health - amount;
    }
}

int main(void) {
    take_damage(7);
    // 该二进制实际先读取 score，再读取 health。
    int observed_score = score;
    int observed_health = health;
    printf("%d %d\n", observed_health, observed_score);
    return 0;
}
```

伪代码中的 observed_score/observed_health 为说明求值顺序而添加，并非恢复的源码变量。极值情况下，机器的 32 位 sub 保留低 32 位；上面的有符号 C 表达式不能被当作所有溢出输入下都等价的可移植 C 实现。

从初始数据和这条 main 路径静态推导，正常运行应输出 `93 100` 后换行并返回 0。这是静态推导，不是运行实测。
