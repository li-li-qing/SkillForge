只读核对顺序：
1. 找到任务状态的权威来源：谁创建任务、谁写入 Running/成功/失败/取消，谁负责生命周期。业务/任务层应拥有执行状态；UI 只消费状态并发出操作意图，不另养一套执行状态。
2. 对齐同一个 task/request ID、对象实例、时间与状态版本，确认日志和当前面板是否指向同一次任务。用任务所有者的当前状态及进度/心跳佐证是否仍在执行，不能仅凭一条历史日志。
3. 沿“状态所有者 → 通知/回调 → UI 数据模型 → 按钮启用条件与样式”逐层核对。记录按钮禁用的具体原因，区分防重复提交、权限/前置条件不足、父级禁用与过期 UI 缓存。若状态已变化但界面未更新，再检查订阅、旧实例和乱序回调。
