# 第三轮：四个既有题面的真实 Agent 行为执行

沿用原题和冻结标准，没有改题追求通过。四个新上下文执行者只读冻结 v4 技能，原始回答已冻结后审阅，文件完整性检查确认技能副本哈希未变。

## 结果

| 原题 | 结果 | 实际依据 |
|---|---|---|
| qt-selection-id | 通过 | 区分 proxy/source/业务 ID，列出 mapToSource 最小落点及重入/异步时保持 ID，提出按 ID 而非行数验收；无源码时不声称修复 |
| lua-foreign-snippet | 边界行为通过，实施缺输入 | 不运行远端 loadstring，要求完整片段、实际加载源码和宿主环境，建议审查后的本地模块；没有凭 Lua 词误套 ArcheRage API |
| lgf-ui-state | **部分通过** | 分清权威状态所有者和 UI 投影，对齐 task/instance/time；但未明确给出冻结标准中的“探针正对照”步骤，不能把四题写成全部通过 |
| experience-negative-evidence | 通过 | 不将 sleep 后暂未复现晋升全库规则，给出未落盘 candidate，区分观察、假设、未知阈值和待验证范围 |

LGF 的缺项是这次回答未展示该行为，不足以证明正式技能存在漏洞：题面已有运行日志，不是“完全没日志”问题，且未提供实际项目。应在下一轮用观察链路失效的明确 fixture 检验，而不是事后改本题验收点或强行修技能。现阶段保留 partial。

## 覆盖与未覆盖
- 真实执行的是技能选择/读取和回答行为，不是字符串关键词检查。
- 没有提供源码、截图、日志文件、插件片段或真实工具端点；执行者没有把它们假装存在。
- Qt 是排序身份问题，不等于 QObject 生命周期真实测试。
- Lua 是远端代码信任/诊断前提，不等于 Lua 解释器运行。
- LGF 题面不含框架身份，执行者正确只使用通用 debugging/UI 资料；不能宣称 LGF 专属行为通过。
- IDA 工具缺失、MCP 公网暴露和真实 UE/Qt/Lua 运行仍未测。
- 三轮使用的是冻结 v4 副本，不把结果自动推广到后续修改版本。
