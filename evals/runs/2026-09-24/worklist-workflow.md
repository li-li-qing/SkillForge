# 清单工作流更新与验证

日期：2026-09-24。范围：skillforge-orchestrator；由用户明确要求将“做事前先列清单、按阶段推进”记入其 SkillForge。

## 变更

- 入口工作流接入按任务规模选择的清单；复杂任务按阶段拆解，小任务用短清单。
- 用户习惯记录本次偏好，详细方法集中在 references/worklist-workflow.md，模板位于 assets/worklist.md。
- 执行简报及 Checkpoint 引用同一台账；确认策略明确清单不是第二次确认，也不是未来研发或提交授权。
- 保留原 explicit-only 调用策略及专业技能动态发现边界；未安装/同步宿主副本，未提交或推送。

## 实际结构检查

在 SkillForge 根目录运行：

```text
python scripts/validate_skills.py skills/skillforge-orchestrator --self-contained
```

修改前：退出码 0，1 个技能、0 错误、1 个独立复制包通过。
修改后：退出码 0，1 个技能、0 错误、1 个独立复制包通过。
skill-creator 的 quick_validate.py 对入口目录检查：退出码 0，Skill is valid。
本次修改文件按 UTF-8 无 BOM、CRLF 保存；未修改校验脚本或运行环境配置。

## 行为样本

两次独立只读 Agent 评测使用相同的三个虚构请求，没有执行虚构项目改动。基线仅读取更新前入口；复核读取更新后的入口及按需参考，未向执行 Agent 提供期待答案。

| 场景 | 更新前观察 | 更新后观察 |
|---|---|---|
| 已授权跨模块工作，拆 WK-0012，旧清单止于 WK-0030 | 可保护未提交工作并继续授权；明确指出技能未规定子项编号、依赖/验收、每轮回填 | 新项从 WK-0031 开始；保留父项并记录替代、更新后继；已完成项另加扩展而不撤销历史；同一授权继续执行 |
| 只规划，要求“1到1000这样列” | 输出规划，但指出现有技能没有规定数量示意、禁止凑数和粒度 | 识别为编号示意，不凑数量；补落点、产出、验收和覆盖；只交规划，不改代码 |
| 直接改一个错别字 | 支持最小改动和跳过重复确认，但未明确台账边界 | 使用定位、替换、定向检查的短清单；不建大型台账、不构建 |

评测规格见 development/skillforge-orchestrator/evals/worklist-cases.json。此次实际运行 WL01～WL03 的对应场景；WL04～WL06 仅建立规格，未单独运行。WL04 的“已完成父项”在更新后 Agent 回答中被主动识别，但不等同独立用例通过。

局限：每个版本一次三场景样本，属于定向模拟，不是多次统计稳定性验证，也没有跨宿主安装或真实工程长周期执行证据。源码 Skill 更新不会自动改变其他位置的安装副本；结构检查不证明所有后续任务都符合流程。
