# SkillForge 验证约定

技能包内 `evals/trigger-cases.json` 保存 `id`、`prompt`、`context`、`expected`（`trigger`、`no_trigger`、`conditional`）、`reason`；`evals/behavior-cases.json` 保存 `id`、`prompt`、`expectations`（可观察的验收点列表）。这些是本仓库用例格式，不是 Agent Skills 标准的必填格式。

行为评测使用同一模型设置、同一工具权限、同一案例和输入材料。每个条件使用新上下文；基线只排除本次新技能，不能保证排除宿主系统规则或已安装技能。记录实际加载内容、工具调用、原始回答和逐项判断，不能把背景能力归因于新技能。具体后端模型 ID 不可见时如实标注，不从产品名称猜版本。

评测者读取一个 `behavior-cases.json`，逐例回答，不读取评分结论；有技能条件额外读取指定技能及任务需要的参考资料。用例要求的是分析或操作方案，不修改真实游戏项目。验收者根据回答中的具体依据判断各项期望，不能以命中某个词或复述技能作为通过依据。

`runs/` 保存真实评测输出和审阅汇总。无法复现的改善写为“未证明”，已经正确的基线写为“保持正确”；不得为了得到失败基线而更改成功标准。单次对比属于冒烟验证，不能证明其他模型、Agent 或真实编辑器任务通过。回答者自查与独立审阅分别标注，两者都不冒充用户验收。

组合验证使用 `composition-cases.json`。触发评测先只提供名称和描述，判断案例应如何选择，再揭示期望；这是描述匹配检查，不是对宿主自动发现机制的实测。首版结构校验只检查规范与可移植性，行为结果单独记录。
