# Qt Skill 接入提示词

将下面内容连同新 Skill 的可读路径交给当前执行 Agent。先让它确认能读取文件，不把文件已复制等同于原生安装。

```text
使用当前可用的 skillforge-orchestrator，并按需读取 skillforge-qt。
若当前环境没有编排器或原生 Skill 调用能力，就直接读取
skillforge-qt/SKILL.md 及它指向的本次相关参考，并说明实际读取方式。

我的项目已决定采用 Qt，不再重新讨论是否继续使用 MFC。
本次先接入这套 Qt 工作规则，读取当前工程与项目指令，
核实 Qt 版本、Widgets/Quick、编译器、C++ 标准、位宽、构建与测试入口。
这些信息以当前工程为准，不使用历史 MFC 记录补齐未知事实。

保留已完成业务功能、核心引擎、平台/大漠适配和存档兼容。
没有当前代码证据时不要猜接口，不因 Qt 接入重写 COM/IPC 拓扑。

涉及 UI 时：优先 Qt 标准控件、布局、QAction 和 Model/View，
处理编辑草稿、后台投影、排序后稳定 ID、焦点/IME/DPI与窗口恢复。
涉及异步时：明确 QObject 拥有关系、所属线程、request/session/generation，
检查取消、迟到结果与退出；不要用 quit、terminate 或阻塞互等伪报完成。

先输出项目事实与未知项、需要读取的参考、当前风险和最小实施范围。
本条仅完成接入核对，不修改产品代码；后续我给具体任务后继续。
如果某项具体任务此前已经被我批准，不因切换 Skill 再重复确认。

最后区分实际运行的构建/单元/UI/Windows/SDK检查和 not_run/blocked，
不能把 Skill 的结构测试或评测题集写成项目运行通过。
```

日常具体任务可直接写：“使用 skillforge-qt，处理 <本次 Qt 需求>”，并明确本次允许修改还是仅审查。安装位置、调用语法和工具权限采用当前宿主实际能力。

完整包保留原有 MFC Skill 供读取旧代码；纯 Qt 日常工作不必加载 MFC。六个 GitHub 项目只是来源，不是待自动安装的依赖列表。
