# 逆向技能首轮补充

## 任务与落点

用户要求拉取 SkillForge，并补充缺少的逆向技能。已在原有 main 上快进到 `08d8957`，开始时工作区干净；不修改游戏，不自动安装工具或同步宿主技能目录，不推送远端。

建议采用两个独立入口：`skillforge-reverse-engineering` 负责二进制、反汇编、类型恢复、托管运行时识别和动态证据；`skillforge-cheat-engine` 负责 CE 安装/实例/目标识别、扫描、地址生命周期、MCP 和 Java collector。两者都自包含，可组合但无兄弟技能硬依赖。

单一大技能容易让一次 CE 版本排错加载完整反汇编资料；为每个 Ghidra/IDA/JDK 版本另建技能则过度拆分。两个入口内部按问题读取参考，保持已有库的分发结构。范围选择是维护者的建议，不冒充用户已确认的偏好。

## 首轮内容

- 通用：文件身份与工具可用性、地址空间和 ABI、伪代码与动态事实、托管对象生命周期、最小复现、证据交接。
- CE：明确实例与当前进程、变化序列扫描、模块相对位置/指针链/AOB 的验证边界、写入读回与超时恢复、版本匹配的 Java/JNI 排障。
- 本次 Minecraft 案例只提炼机制；实际地址、玩家身份、安装位置和运行进度不进入可移植技能。保留已有试验摘要的指纹与适用范围，不把历史结果说成本轮重测。
- 加入触发题、行为题及实际验证报告。结构通过、行为冒烟和真实游戏验证分开记录。

## 来源与裁剪

阅读固定提交的三个社区技能和 CheatEngine.Mcp README；技术规则用 PE 官方规范、JNI 官方规范及本机 CE 源码切片交叉核对。仅独立整理机制，不复制第三方脚本、完整技能或二进制。

不引入默认上传样本、批量安装整套工具、强制某个宿主、默认后台服务、忽略授权的指令。未知样本的隔离要求与用户自有正常软件的调试分开处理。

## 验证安排

改动前已有 11 个技能通过自包含校验。先运行无新技能的三个隔离题，冻结原始回答；然后运行带新技能的同题冒烟。基线已正确的项标“保持正确”，不宣称改善。新增只读 PE 地址核验工具先写合成文件测试，再实现；不执行被分析样本。最终运行库校验、工具测试及索引发现检查。
