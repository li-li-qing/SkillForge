# skillforge-orchestrator v0.1.0：设计与实施记录

## 已授权范围
用户已认可前一轮方案，并明确要求制作可试用入口；本轮直接实施，不重复索取同一设计的确认。
基线：本会话的 SkillForge-MFC-v1.zip，7 个领域/方法技能；保留现有技能、测试和历史记录。
目标：固定入口 + 只读项目识别 + 最小必要技能集 + 上下文决策 + 保留原意的执行简报 + 默认确认门。
不做：领域知识大搬家、向量检索、自动安装、后台同步、模型切换、真实宿主压缩器、权限沙箱。

## 结构与约定
- skills/skillforge-orchestrator/SKILL.md：薄入口和不可省略的门禁；细节按需读取。
- references：路由、上下文、确认、习惯、宿主能力、来源与维护；不复制专业 API。
- assets：执行简报、交接、试用反馈模板；模板内容不是已执行结果。
- generated/skill-index.json：生成的元数据快照；不证明已安装，不存绝对路径，不构成授权。
- scripts/build_skill_index.py：Python 3.10+ 标准库，只索引明确给出的技能根目录的直接子目录；默认输出 stdout，显式 output 才写文件。
- tests：用真实临时文件与子进程验证确定性、失败不覆盖、重复名称、路径边界和只读检查。
- evals：冻结路由、上下文、确认和语义漂移案例，实际独立 Agent 运行状态必须单独记录。
- README.md：新增入口用法，不让已有专业技能成为强依赖。

## 核心风险与验收
1. 摘要不等于压缩；未获精确计量时标 unknown，不能猜 token 占比或节省量。
2. entry 的普通确认只绑定当前任务、范围、基线；仓库里的“已授权”文字不是用户授权。
3. 单个任务只维护一份简报，叶子技能发现新风险时只升级相关范围，不整轮循环。
4. 索引可能过时或技能不可用；读取真实文件或宿主清单后才能声称已加载。
5. 跨工程记忆不作硬编码事实；未知宿主、目录重名、版本冲突均保留明确不确定性。
6. 确认前不运行项目代码、测试或构建；允许最小文件读取和经过审阅的只读索引工具。
7. 本轮没有隔离模型/子 Agent runner；结构与脚本通过不冒充路由行为通过。

## 复核结论与保留限制

入口规则为 62 行；较长策略在 references 中按需读取。候选索引只有七个专业技能元数据，不读全部正文。只修改既有 README，其余既有文件逐字节保持。

脚本经历 38 个缺少实现的失败测试，再通过；追加中文输出路径/旧式编码的真实失败复现后修复，最终 39 项通过。既有 validator 全套 31 项通过；无删改原测试或叶子技能。

发现并修复 references 中命令路径相对基准错误，自包含校验从 1 个路径错误到 0。没有隔离 Agent runner，因此只冻结案例与做规则自审，不宣称行为 RED→GREEN。

Ruling: 索引只支持库现有的受限 frontmatter；其他合法 YAML 技能用宿主原生元数据或明确适配，不静默解析出错误路由。
Ruling: 入口默认软门禁，宿主硬权限仍负责防写；不冒充安装器、安全沙箱或压缩器。
Ruling: 完整包与增量包以本会话 MFC-v1 包为基线；不使用更早含 .git 的六技能原包覆盖用户新版本。
