# SkillForge 0.3.0：个人协作连续性与经验闭环

日期：2026-10-15。来源：本次用户逐项确认的战略讨论及“先开始编写”指令。
本轮只修改上传包的隔离副本；不接触用户本地共享总目录，不安装、不推送、不修改产品工程。

## 已确认的设计

- 个人协作习惯跨项目、跨 Agent 延续；工程事实按当前项目核验，临时妥协不升级为长期偏好。
- 新任务未指定等级，先问 A/B；已明确指定或同一任务继续不重复问。A自主、B协同，不等同于实现/设计的任务性质。
- A在既定边界内推进：有依据的自己做；低风险可逆细节记录假设；重大未决项隔离并继续独立工作；不越权、不假报完成。
- B的重要取舍由 AI 解释场景、利弊、成本、推荐理由后请用户决策；普通实现细节自己负责；非阻断建议不拖进度。
- 始终理解并完善任务，不以长提示词及再次确认作为固定门槛。只分析/只提示词不实施；明确实施后不重复等待。
- 主动质疑方案而非机械照做；承担共同根因、必要关联修改和影响面回归，不顺手做无关重构。
- 高返工成本且证据不足的新路线先做最小验证；没有实测就写 not_run；技术路线变更仍受既定边界约束。
- 验证、失败经验及个人习惯主动沉淀；按职责维护技能，无冲突且证据充分的内容核对后生效，有冲突先保留。
- 多 Agent 共用总目录且可能并发更新：记录独立、正式写入串行核对、保留来源与条件、可追溯撤回；不能用最后写入者覆盖。
- 优先复用已有技能，只有稳定可复用的独立职责才新增。本轮新增工程前置验证、经验维护两个方法技能；不新增每Bug技能。

## 架构与文件归属

入口保留纯文本 portable core，个人习惯权威内容仍在其 references/user-workstyle.md。
工程前置验证技能负责选型/性能/UI/网络的触发和证据；专业技能提供领域合同。
经验维护技能负责记录/晋升/冲突/撤回；附可选本地文件保护工具，不是后台服务或多 Agent 调度平台。
已有8个叶子技能保持可独立使用；共享个人习惯需由入口显式携带，不能假设未加载的技能自动生效。
运行目录历史工具移入 development/history；宿主 metadata 移至外部 adapters；唯一现行索引工具位于 development/tools。

## 验收重点

A/B新含义与旧批准不冲突；只分析+A不实施；无人回复不默认为同意；短提示承接约定。
LAssist案例不泛化成所有节点图低效；UE大型同步主动评估FastArray，不把网络API用于Qt。
UI新方向先展示和验证，已有布局小修不过度审批；多写入者旧版本不能覆盖新规则。
脚本只证明机械文件保护，不判断语义真实性，不是权限沙箱；任意非协作写入者仍可绕过。
只有真实 Agent 对照才证明行为效果：本环境未提供独立 Agent 执行器，行为案例记 not_run，不用文本检查冒充。

## 执行说明

无独立Agent执行器参与，本轮按现有讨论直接实现并自审；未将静态合同或脚本测试称为模型行为通过。旧便携测试不删断言；发布前复核变更包能否准确重建工作副本。
