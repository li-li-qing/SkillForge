# 从项目问题到可复用经验

技能库的维护者在修复完成后执行此流程。本说明不创建自动任务，也不授权 Agent 在每次项目会话中自行改动其他仓库。

## 收录步骤

1. 保存足以重建判断的最小证据：错误文本、相关源码位置、运行条件、版本、复现或诊断结果。去掉账号、令牌、个人路径与无关日志。
2. 区分观察、假设与确认的原因。修复后“暂时没再发生”不能单独证明原解释正确。
3. 对旧资料或社区方案，核对目标版本的源码、官方文档或最小复现。若资料冲突，记录各自覆盖的条件；没有结论时保持候选状态。
4. 确定归属：可复用方法放到对应技能的 `references/`；项目资产、运行期入口、网络拓扑和工作进度留在项目文档。一个问题跨技能时按职责提炼，不复制整份项目历史。
5. 补一个能检验该结论的行为案例或反例，重跑受影响的技能及组合案例。记录未覆盖环境，删除失效建议而非不断追加例外。

## 单条记录

每条用紧凑段落或表格记录以下字段；这是经验资料格式，不要求每次面向用户的回答都照模板输出。

| 字段 | 要记录的事实 |
|---|---|
| 编号与状态 | 稳定编号；候选、文档/源码已核验、运行已复现或已失效 |
| 症状与触发条件 | 用户看到什么；发生在哪个生命周期、输入、数据或环境条件下 |
| 适用版本 | 引擎、客户端、框架、插件版本；无法确认时明确未知 |
| 证据 | 可定位的源码符号/提交、官方链接、复现结果；不是仅“经验如此” |
| 原因 | 哪个机制解释现象；仍有竞争假设时不要写成已确认根因 |
| 修复 | 改动与原因的关系；临时缓解和长期修复分别标注 |
| 验证结果 | 实际执行的检查、结果、未执行部分与回归条件 |

## 本次取材边界

- LGF UMG 笔记：可见性、鼠标事件、控件绑定和布局规则是候选；技术结论逐条核查。
- Replicated Suite 笔记：区分“API 不可用/覆盖不足/确实为空”、核查加载入口与订阅链的方法可复用。当前客户端 API 是否可用，本次没有运行验证。
- Advanced UI 笔记：信息优先级、实时几何稳定、可恢复工作台作为设计方法提炼；具体布局是否好用，仍需在目标界面与分辨率下验证。

这些原始本机资料不随新技能包分发。每个已收录参考都自带足够说明和可用的技术证据，不要求其他 Agent 能访问作者电脑。
